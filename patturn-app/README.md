# 🏺 Patturn — استودیوی طراحی پارامتریک سفال

نرم‌افزار طراحی برای سفالگران: **فرم سه‌بعدی ← الگوی بی‌درز ← قالب چندتکه ← خروجی STL/SVG/DXF**.
نسخهٔ اصلی: **اپ نصب‌شدنی ویندوز با اجرای کاملاً آفلاین** (قانون R-014) — نسخهٔ وب همان SPA است.

## ⚡ شروع سریع (توسعه)

```bash
npm install          # نصب وابستگی‌ها
npm run lint         # قواعد صحت JS/TS/TSX؛ بدون هشدار
npm test             # تست‌های طلایی و ماژولی — باید همه سبز شوند
npm run dev          # اجرای اپ وب روی http://localhost:5173
npm run build        # build تولیدی اپ وب
```

## 🪟 بسته‌بندی دسکتاپ ویندوز (روی ویندوز ۱۰/۱۱)

پیش‌نیاز: [Rust (stable)](https://rustup.rs) + Microsoft WebView2 (روی Win10/11 پیش‌فرض نصب است)

```bash
npm install
npm run desktop:build    # → تولید نصب‌کننده NSIS/MSI در apps/desktop/src-tauri/target/release/bundle/
npm run desktop:dev      # اجرای حین توسعه
```

خروجی پیکربندی فعلی: نصب‌کنندهٔ آزمایشی NSIS؛ نصب، ارتقا و حذف تمیز هنوز روی ویندوز آزموده نشده‌اند.

## فایل‌های بومی دسکتاپ

در محیط Tauri، خروجی‌ها از دیالوگ ذخیرهٔ بومی و فایل پروژه از دیالوگ بازکردن استفاده می‌کنند؛
نسخهٔ مرورگر همچنان از دانلود و انتخاب فایل استاندارد استفاده می‌کند. آداپتور دسکتاپ فقط در
محیط Tauri بارگذاری می‌شود. دسترسی خواندن/نوشتن برای مسیر انتخاب‌شدهٔ کاربر است و scope سراسری اضافه نشده است.
لغو دیالوگ نوشتنی انجام نمی‌دهد؛ فایل پروژه قبل و بعد از خواندن محدودیت اندازه دارد و سپس اعتبارسنجی می‌شود.

تست‌های خودکار آداپتور با درایور شبیه‌سازی‌شده اجرا می‌شوند. ساخت Rust، نصب‌کننده و بررسی واقعی دیالوگ‌ها
روی ویندوز در این محیط انجام نشده‌اند؛ بند ۹.۶ تا انجام این بررسی باز است.


### بکاپ پوشه‌ای دسکتاپ

پس از ذخیرهٔ خودکار در Tauri، یک فایل فشردهٔ `.patturn` در `AppLocalData/backups` ساخته می‌شود.
پنل «بکاپ پوشهٔ برنامه» فهرست و بازیابی تأییدشده را ارائه می‌کند. تا ۱۰ نسخه نگه داشته می‌شود؛
فقط فایل‌های با الگوی نام اختصاصی برنامه پاک‌سازی می‌شوند و فایل‌های موقت و نامرتبط نادیده گرفته می‌شوند.
نوشتن ابتدا در فایل `.tmp` و سپس با تغییر نام در همان پوشه انجام می‌شود؛ این کار تضمین دوام در قطع برق نیست.
خطای بکاپ جدا از موفقیت ذخیرهٔ محلی گزارش می‌شود. پوشه روی همین دستگاه است؛ برای بکاپ مستقل فایل پروژه را به محل دیگری منتقل کنید.
تست فایل‌سیستم با درایور شبیه‌سازی‌شده است و آزمون عملی ویندوز برای تکمیل بند ۹.۸ باقی مانده است.


## بررسی خودکار و کامپایل ویندوز

گردش‌کار `.github/workflows/quality.yml` روی تغییرات برنامه، بررسی TypeScript، تست‌ها و ساخت وب را در لینوکس
و کامپایل فایل اجرایی دسکتاپ را در `windows-latest` اجرا می‌کند. دستور `npm run desktop:check` فقط
فایل اجرایی را بدون نصب‌کننده می‌سازد. خروجی CI با نام `windows-compile-check` هفت روز نگه داشته می‌شود
و شامل فایل اجرایی آزمایشی و Cargo.lock حل‌شده است؛ انتشار رسمی یا فایل امضاشده محسوب نمی‌شود.

کامپایل موفق جای آزمون اجرای رابط، فایل‌سیستم، نصب، ارتقا، حذف یا حالت آفلاین روی ویندوز را نمی‌گیرد.
اسکریپت typecheck با Node اجرا می‌شود و به Bash وابسته نیست. آیکون اختصاصی با
`python scripts/make-icons.py` (نیازمند Pillow فقط برای بازتولید آیکون) ساخته می‌شود؛ فایل‌های آماده در مخزن هستند.


### گزارش بستهٔ جاوااسکریپت

پس از `npm run build`، دستور `npm run bundle:report` اندازهٔ ورودی و وابستگی‌های ثابت و نیز مجموع
ادیتور با نمایشگر سه‌بعدی را از manifest واقعی ساخت گزارش می‌کند. نمایشگر در اولین رندر درخواست می‌شود؛
بنابراین جداشدن chunk آن به معنی حذفش از هزینهٔ راه‌اندازی سه‌بعدی نیست. موتور PDF و فونت فقط هنگام
خروجی PDF یا ZIP بارگذاری می‌شوند و از دارایی‌های محلی برنامه هستند، نه CDN. تابع `toDimensionPdf` اکنون async است.
این گزارش اندازهٔ فایل است، نه سنجش LCP یا آزمون مرورگر؛ بند عملکرد تا رسیدن به همهٔ معیارها باز می‌ماند.


### نصب‌کنندهٔ آزمایشی NSIS در CI

پس از کامپایل، CI با `npm run desktop:installer` نصب‌کنندهٔ NSIS بدون امضای ناشر را می‌سازد؛
`npm run installer:checksums` هش SHA-256، شناسهٔ commit/اجرا و راهنمای آزمون را کنار آن می‌نویسد.
آرشیو جداگانهٔ `windows-nsis-test` هفت روز نگه داشته می‌شود؛ انتشار عمومی یا تأیید نصب محسوب نمی‌شود.
راهنمای کامل در `docs/windows-test-guide.txt` است. روی دستگاه اصلی بدون بکاپ آزمایش نکنید و برای اجرای فایل
بدون امضا محافظ‌های سیستم را غیرفعال نکنید. پیکربندی فعلی در صورت نبود WebView2 برای نصب آن اینترنت می‌خواهد؛
نصب اولیهٔ کاملاً آفلاین هنوز هدف تکمیل‌نشده است. هش کنار فایل فقط کنترل خرابی دانلود است، نه امضای ناشر.


### معنای ظرفیت و ضخامت در ادیتور فعلی

ظرفیت از پروفیل انتخاب‌شده با کسر شعاعی ضخامت و بالابردن کف محاسبه می‌شود؛ این روش تقریب ظرفیت است،
نه آفست عمود بر سطح. STL فرم همچنان مدل بیرونی توپر برای ساخت قالب است، نه ظرف توخالی با ضخامت قابل پرینت.
مواد پنل قالب پس از ساخت از جمع حجم واقعی قطعات محاسبه می‌شوند و شامل پرت نیستند.


### واگرد و ازنو

دکمه‌های «واگرد» و «ازنو» در هدر، عنوان تغییر را نمایش می‌دهند و تا ۵۰ عمل پارامتری را نگه می‌دارند.
`Ctrl+Z` برای واگرد و `Ctrl+Y` یا `Ctrl+Shift+Z` برای ازنو است؛ روی مک `Meta` نیز پشتیبانی می‌شود.
هنگام فوکوس ورودی‌ها، رفتار بومی ویرایش متن حفظ می‌شود. کشیدن اسلایدر یک عمل گروهی است؛
با تغییر جدید پس از واگرد، شاخهٔ ازنو پاک می‌شود. این تاریخچه در حافظه است و با فایل پروژه ذخیره نمی‌شود؛
تاریخچهٔ ذخیرهٔ محلی و بکاپ پوشه‌ای مستقل‌اند.


### حالت ساده و حرفه‌ای

در بالای پنل پارامترها، «ساده» کنترل فنی سگمنت را در بخش بازشدنی «تنظیمات پیشرفته» قرار می‌دهد؛
«حرفه‌ای» آن را مستقیم نمایش می‌دهد. مقدار فعلی همیشه حفظ می‌شود و حتی در حالت بسته در خروجی اعمال می‌شود.
این انتخاب فقط نمای جلسه است، نه پارامتر پروژه؛ با تغییر آن، ظرفیت، مش و تاریخچهٔ ویرایش تغییر نمی‌کنند.

ساخت NSIS در [اجرای 44924022342](https://github.com/pranses2011/Sahand_Patturn/actions/runs/44924022342)
موفق شد و آرتیفکت `windows-nsis-test` تولید شد. این تأیید بسته‌بندی است، نه تأیید نصب یا اجرای ویندوز.

### محدودهٔ SVG الگو

خروجی مستقل SVG و فایل داخل ZIP از ضخامت خط همان الگوی پیش‌نمایش استفاده می‌کنند و واحد mm دارند.
بوم با `clipPath` محدود می‌شود؛ این برش نمایشی است و مسیرهای بیرون بوم را هندسی حذف نمی‌کند.
نرم‌افزارهای برش که clip را نادیده می‌گیرند نیازمند آماده‌سازی جداگانه‌اند. SVG فعلی مسیر مرکزی با stroke است،
نه کانتور ضخیم‌شدهٔ آمادهٔ برش یا استنسیلِ دارای پل. بررسی ایمنی خروجی، جایگزین اعتبارسنج کامل دستور زبان SVG نیست.

### محدودهٔ موتور DXF

موتور R12 فقط مسیرهای خطی `M/L/H/V/Z` (مطلق و نسبی) را می‌پذیرد؛ زیرمسیرهای جدا مستقل می‌مانند
و بسته‌بودن کانتور در پرچم POLYLINE ثبت می‌شود. لایه‌های `outline` و `detail` تعریف می‌شوند.
دایرهٔ استاندارد موتور (دو نیم‌قوس هم‌شعاع و کامل) به CIRCLE دقیق تبدیل می‌شود؛ تک‌قوس دایروی با شعاع‌های برابر و چرخش صفر نیز به ARC تبدیل می‌شود؛ بیضی و سایر منحنی‌ها صریحاً رد می‌شوند تا فایل ناقص موفق اعلام نشود.
عدد مختصات در مقیاس میلی‌متر نوشته می‌شود؛ هنگام ورود در CAD واحد mm را انتخاب کنید.
دکمهٔ DXF خط، دایره و قوس در بخش خروجی فعال است؛ Scale و Seigaiha با کاشی مربعی پشتیبانی می‌شوند و Wave با فعال‌سازی تقریب Bézier پشتیبانی می‌شود. خواندن خروجی در CAD خارجی هنوز آزموده نشده است.


DXF دانلودشده از ادیتور اکنون هندسهٔ خط و دایره را به مستطیل ۳۰۰×۳۰۰ میلی‌متر محدود می‌کند:
خط با تقاطع دقیق و دایره با کمان‌های ARC بریده می‌شود. این کار ضلع تازه‌ای در مرز بوم برای بستن
کانتور نمی‌سازد؛ بنابراین فایل هنوز کانتور بستهٔ آمادهٔ برش یا استنسیل پل‌دار نیست.
برش SVG همچنان صرفاً نمایشی است. قابلیت خواندن LINE/ARC در CAD مقصد باید جداگانه آزموده شود.


### تقریب Bézier در DXF

دانلود DXF ادیتور برای موج از تقسیم تطبیقی De Casteljau با تلورانس ۰٫۰۵ میلی‌متر استفاده می‌کند.
فاصلهٔ نقاط کنترل هر قطعه تا پاره‌خط معیار پذیرش است؛ تقریب پیش از برش بوم انجام می‌شود.
این تلورانس در هندسهٔ مدل و با محاسبات ممیز شناور است، نه گواهی دقت ابزار برش یا تلورانس نهایی قطعات بریده‌شده.
موتور API بدون گزینهٔ صریح `bezierToleranceMm` همچنان C/c را رد می‌کند؛ با گزینه، وضعیت تقریب در توضیح DXF ثبت می‌شود.
فعلاً فقط Bézier مکعبی C/c پشتیبانی می‌شود، نه همهٔ دستورهای منحنی SVG. سقف تقسیم و عمق باعث خطا می‌شود، نه پذیرش تقریب نادقیق.


### بازخوانی مستقل DXF در تست‌ها

تست‌های round-trip با `dxf-parser` (فقط وابستگی توسعه) خروجی هر ۱۲ الگو را مستقلاً می‌خوانند؛
نوع موجودیت‌ها، لایه‌ها، مختصات خطوط، مرکز/شعاع و نمونه‌های قوس‌ها پس از برش کنترل می‌شوند.
پرچم بسته‌بودن POLYLINE بدون برش هم بازخوانی می‌شود. این بررسی خودکار ساختار و نمونه‌های هندسه است؛
جای آزمون واردکردن فایل، مقیاس و جهت در نرم‌افزار CAD یا دستگاه برش واقعی را نمی‌گیرد.

بستهٔ ZIP ساخت اکنون DXF الگو را نیز کنار SVG در `pattern/` دارد. DXF از هندسهٔ ورودی در خود بسته‌ساز
تولید می‌شود؛ پسوند خام DXF در فایل‌های اضافی مجاز نیست. شکست تبدیل، برخورد نام یا مسیر ناامن کل بسته را رد می‌کند.
`parameters.json` تنظیمات برش بوم و تقریب ۰٫۰۵mm پیش از برش را ثبت می‌کند و فهرست اندازهٔ فایل‌ها شامل DXF است.

در بخش الگو، انتخاب «تخت ۲بعدی / روی فرم ۳بعدی» پیش‌نمایش بافت روی فرم را از زیر پوشش نمای تخت
در دسترس قرار می‌دهد. هنگام نمای تخت، کامپوننت WebGL نصب نیست و حلقهٔ رندر پنهان اجرا نمی‌شود؛
اما نمایشگر فرم در شروع برنامه همچنان بارگذاری می‌شود و این تغییر به‌تنهایی هدف حجم اولیه یا LCP را برآورده نمی‌کند.
انتخاب نما فقط وضعیت جلسه است و هندسه، خروجی STL، فایل پروژه یا تاریخچهٔ پارامترها را تغییر نمی‌دهد.
نگاشت سه‌بعدی تقریب تصویری است، نه برجسته‌سازی هندسی یا تأیید مقیاس نهایی الگو روی سطح.


### خطای نمایشگر گرافیکی

خطای رندر یا راه‌اندازی WebGL و رویداد قطع کانتکست، پیش‌نمایش را به پیام فارسی و دکمهٔ تلاش دوباره تبدیل می‌کند.
مرز خطا فقط دور نمایشگر است؛ کنترل‌ها و وضعیت پروژه بیرون آن می‌مانند. تلاش دوباره فقط پیش‌نمایش را از نو می‌سازد،
نه پروژه را. خطای بارگذاری تنبل نمایشگر نیز در همین محدوده نمایش داده می‌شود؛ اگر بارگذاری ماژول در مرورگر
کش شده و شکست خورده باشد، ممکن است پس از ذخیرهٔ فایل پروژه نیاز به بارگذاری دوبارهٔ صفحه باشد.
تست‌های React خطای رندر و effect و حفظ وضعیت همسایه را بررسی می‌کنند؛ قطع واقعی GPU در مرورگر/ویندوز هنوز آزموده نشده است.


### وضعیت تحویل خروجی

ذخیرهٔ خروجی‌ها در ادیتور یک دیالوگ در هر لحظه دارد؛ درخواست دوم در زمان ذخیره پذیرفته نمی‌شود.
موفقیت دسکتاپ فقط پس از پایان نوشتن گزارش می‌شود و لغو دیالوگ از خطا جداست. برای خطا، همان بایت‌های
خروجی جهت تلاش دوباره نگه داشته می‌شوند؛ این خروجی مربوط به لحظهٔ تولید است، نه تغییرات بعدی پروژه.
شروع خروجی جدید، دادهٔ تلاش دوبارهٔ قبلی را کنار می‌گذارد. خطای نوشتن ممکن است فایل مقصد ناقص بگذارد؛
این مسیر هنوز ذخیرهٔ اتمی یا تضمین قطع برق نیست. در مرورگر فقط ارسال درخواست دانلود تأیید می‌شود، نه ذخیرهٔ واقعی.

### تست مرورگر

```bash
npm ci
npx playwright install --with-deps chromium
npm run build
npm run test:e2e
```

دو سناریوی Playwright روی خروجی production در Chromium بررسی می‌شوند: حفظ رابط هنگام غیرفعال‌بودن
WebGL، تغییر پارامتر و Undo/Redo، رفت‌وبرگشت فایل پروژه، انتخاب الگو و دانلود SVG/DXF.
برای مرورگر ازقبل‌نصب‌شده می‌توان `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` را تنظیم کرد.
مسیر جایگزینِ بدون WebGL عمداً آزموده می‌شود؛ این تست رندر واقعی GPU، نصب ویندوز یا کل مسیر قالب‌سازی نیست.
CI وب همین تست‌ها را اجرا می‌کند و trace شکست را هفت روز نگه می‌دارد؛ فایل‌های تست فقط دادهٔ ساختگی دارند.
گزارش‌های مرورگر و باینری‌های آزمایشی در Git نگهداری نمی‌شوند. موفقیت اجرای جدید CI باید جداگانه بررسی شود.
پس از ارتقای هدفمند Vite/Vitest و Zod، گزارش کامل `npm audit` و گزارش production در بررسی محلی صفر مورد شناخته‌شده نشان دادند.


### ارتقای اعتبارسنجی پروژه

Zod در schema و storage به ۴٫۶٫۷ ارتقا یافت تا هشدار `GHSA-mrhx-c7xc-m3w5` رفع شود؛
دیکشنری پارامترها با کلید رشته‌ای صریح به API جدید منتقل شد. نسخهٔ فرمت پروژه تغییر نکرده است؛
تست‌های فایل فشرده، تاریخچه، بکاپ، کتابخانه و رفت‌وبرگشت پروژه در Chromium همچنان موفق‌اند.
`npm audit --omit=dev` در بررسی پس از ارتقا صفر مورد شناخته‌شده گزارش کرد؛ این تضمین امنیت کامل نیست.
حجم خام ادیتور همراه نمایشگر پس از ارتقا حدود ۸۵۱KB است؛ هدف ۶۰۰KB و LCP واقعی همچنان بازند.


### ابزارهای ساخت و تست

نسخه‌های فعلی: Vite ۸٫۳٫۸، افزونهٔ React ۶٫۳٫۰ و Vitest ۵٫۱٫۱.
Node پشتیبانی‌شده مطابق `engines`: نسخهٔ ۲۲٫۱۲ به بالا در شاخهٔ ۲۲، شاخهٔ ۲۴، یا ۲۶ به بالا؛ CI از Node 22 استفاده می‌کند.
پیکربندی JSX تست‌ها به OXC و مسیرهای پیکربندی به `import.meta.dirname` منتقل شد.
نصب تمیز `npm ci --ignore-scripts`، بررسی نوع‌ها، تست‌ها، ساخت worker و دو smoke test مرورگر محلی تأیید شدند.
در گزارش تازهٔ کامل `npm audit` صفر مورد شناخته‌شده گزارش شد؛ این نتیجه تابع پایگاه هشدارهای زمان بررسی است.
تأیید ابزار جدید در CI ویندوز و نصب واقعی دسکتاپ همچنان نیازمند بررسی جداگانه‌اند.
هشدار حجم chunk نمایشگر و externalization ماژول node:module در manifold هنوز وجود دارد؛ هدف عملکرد بسته نشده است.


### آزمون WebGL نرم‌افزاری

Playwright اکنون دو پروژه دارد: `no-webgl` برای دو سناریوی مسیر جایگزین و `software-webgl` برای
دو سناریوی SwiftShader. در حالت نرم‌افزاری، فراخوانی رسم هندسه، سه بار جابه‌جایی تخت/سه‌بعدی،
قطع کانتکست با افزونهٔ `WEBGL_lose_context` و تلاش دوباره با حفظ ضخامت پروژه بررسی می‌شوند.
هر چهار تست در Chromium محلی موفق شدند؛ اتصال آن‌ها به CI اضافه شده ولی نتیجهٔ اجرای جدید جداگانه باید بررسی شود.
فراخوانی draw به معنی تطابق تصویری پیکسل‌ها نیست؛ آزمون رگرسیون تصویری و حافظهٔ GPU انجام نشده است.
فلگ `--enable-unsafe-swiftshader` فقط برای مرورگر تست با داده‌های ساختگی است، نه تنظیم پیشنهادی مرورگر کاربر.
GPU فیزیکی، درایور ویندوز و قطع سخت‌افزاری واقعی هنوز تأیید نشده‌اند.

ورودی بافت نمای سه‌بعدی اکنون memoized است و در رندرهای نامرتبط ادیتور تغییر هویت نمی‌دهد؛
اثر تعویض هندسه/بافت صرفاً با پارامترهای مرتبط اجرا می‌شود. مسیر بافت فقط یک کاشی با seed و پیش‌فرض‌های
همان الگو تولید می‌کند، نه هزاران مسیر بوم کامل. بوم ۳۰۰×۳۰۰ برای نمایش تخت و خروجی SVG/DXF مستقل باقی است.
تست‌ها پایداری هویت و محدودبودن بوم پیش‌نمایش را بررسی می‌کنند؛ اندازه‌گیری زمان GPU یا LCP از این تغییر استنتاج نمی‌شود.

### مسیر یکپارچهٔ قالب و بسته بدون سرویس خارجی

تست پنجم Chromium فرم مرجع را با ۲۴ سگمنت، الگوی موج، ساخت قالب و دانلود ZIP طی می‌کند.
تمام HTTP(S) خارج از origin محلی دارایی‌ها مسدود است و تست نبود درخواست خارجی را بررسی می‌کند.
آرشیو دانلودشده باز می‌شود: اندازهٔ STL، PDF، SVG، DXF با خوانشگر مستقل، پروژهٔ فشرده، تنظیمات و manifest بررسی می‌شوند.
این آزمون دو اشکال را آشکار و رفع کرد: فرم مرجع ادیتور باید برای CSG و STL با دهانهٔ بسته ساخته شود؛
فونت رابط نیز به‌جای Google Fonts باید از فایل محلی بارگذاری شود. فونت Regular با مجوز OFL در `public/fonts/` قرار دارد؛
وزن‌های پررنگ مرورگر از همین فونت شبیه‌سازی می‌شوند. محاسبهٔ ظرفیت همچنان از پروفیل حفرهٔ جداست.
سرور محلی در تست روشن است؛ این ادعای پشتیبانی آفلاین مرورگر با service worker یا آزمون نصب آفلاین ویندوز نیست.


جابجایی بین تب‌های «قالب» و «خروجی» اکنون وضعیت فعال‌بودن قالب را ثابت نگه می‌دارد؛
هندسه بدون تغییر دوباره ساخته نمی‌شود و محفظه‌ها/مادرقالب‌های محاسبه‌شده با این جابه‌جایی حذف نمی‌شوند.
تست یکپارچه دو محفظهٔ جعبه‌ای (چهار نیمه) می‌سازد، بین این دو تب رفت‌وبرگشت می‌کند و حضور همان
چهار STL را در ZIP بررسی می‌کند. تغییر هندسه یا انقباض نتایج مشتق‌شده را نامعتبر می‌کند؛ سرزدن به تب فرم/الگو بدون تغییر هندسه دیگر آن‌ها را پاک نمی‌کند؛
این اصلاح ذخیرهٔ دائمی مادرقالب‌ها در فایل پروژه نیست.


قالب فعلی در حافظه به snapshot ورودی‌های هندسه/پروفیل/انقباض وابسته است. تغییر صرفِ الگو، نمای کنترل‌ها یا تب‌ها
آن را نامعتبر نمی‌کند؛ ورودی هندسی جدید بلافاصله نتیجهٔ قدیمی را از مسیر خروجی کنار می‌گذارد و ساخت جدید فقط
هنگام نیاز در قالب/خروجی انجام می‌شود. این کش تک‌نتیجه‌ای است، نه تاریخچهٔ دائمی مش‌ها.
تست مرورگر علاوه بر حفظ چهار نیمه در جابه‌جایی همهٔ تب‌ها، سگمنت را تغییر می‌دهد و ZIP دوم را برای نبود
محفظهٔ قدیمی و ثبت سگمنت جدید بررسی می‌کند.

### خطای ساخت قالب و خروجی مستقل فرم

خطای CSG/WASM از نتیجهٔ اعتبارسنجی فرم جداست و در قالب/خروجی با پیام و دکمهٔ «تلاش دوبارهٔ ساخت قالب»
دیده می‌شود. تست ششم مرورگر همهٔ درخواست‌های WASM را قطع می‌کند، خطای قابل‌بازیابی را می‌بیند،
STL فرم را دانلود می‌کند و پس از اجازهٔ بارگذاری WASM، ساخت موفق قالب را بدون تغییر پارامترها تأیید می‌کند.
اعتبارسنجی فرم در محاسبهٔ خالص memoized انجام می‌شود؛ مش نامعتبر به CSG داده نمی‌شود.
دکمهٔ عمومی STL اکنون صریحاً فرم بیرونی را صادر می‌کند، نه مش فاصله‌گذاری‌شدهٔ نمای قالب؛
قطعات قالب خروجی‌های جداگانه دارند. دانلود خروجی دیگر وضعیت پروژه را ویرایش‌شده علامت نمی‌زند.


### رندر هنگام نیاز

نمایشگر سه‌بعدی به‌جای حلقهٔ رسم همیشگی، با تغییر هندسه، اندازه یا دوربین فریم درخواست می‌کند.
درخواست‌های هم‌زمان ادغام می‌شوند و OrbitControls تا پایان damping فریم بعدی را درخواست می‌کند؛
بعد از آرام‌گرفتن دوربین رسم متوقف می‌شود. تست SwiftShader توقف فراخوانی رسم در بازهٔ سکون و ازسرگیری
پس از حرکت چرخ ماوس را بررسی می‌کند. این آزمون شمارش draw است، نه اندازه‌گیری مصرف باتری، زمان GPU یا LCP.

### ویرایش عددی بدون محدودسازی هنگام تایپ

ورودی‌های عددی پیش‌نویس مستقل دارند؛ پاک‌کردن عدد و تایپ تدریجی اعشار، هندسه را در هر کلید تغییر نمی‌دهد.
Enter یا خروج از فیلد مقدار را به بازه و گام کنترل محدود و ثبت می‌کند؛ ورودی خالی/نامعتبر به مقدار قبلی برمی‌گردد
و Escape ویرایش را لغو می‌کند. اسلایدر زنده است و حرکت صفحه‌کلیدی آن هم در تاریخچه گروه‌بندی می‌شود.
تست هفتم Chromium پاک‌کردن، لغو، تایپ ۱۲٫۵٪ و Undo پس از ثبت را بررسی می‌کند.

ناوبری چهار بخش ادیتور دکمه‌های بومی داخل landmark با عنوان «بخش‌های طراحی» دارد؛
Tab/Shift+Tab برای جابه‌جایی فوکوس و Enter/Space برای انتخاب فعال‌اند و بخش جاری با `aria-current` مشخص می‌شود.
تست هشتم Chromium انتخاب بخش‌ها با صفحه‌کلید را بررسی می‌کند. این به معنی ممیزی کامل دسترس‌پذیری یا آزمون screen reader نیست.

### آزمون خرابی ذخیرهٔ محلی در مرورگر

دو سناریوی افزوده، نوشتن تاریخچه را با `QuotaExceededError` شبیه‌سازی‌شده متوقف می‌کنند یا JSON خراب
در localStorage می‌گذارند. تست‌ها باقی‌ماندن بایت‌های قبلی، نبود علامت موفقیت اشتباه، بازیابی با تلاش دوباره و
حفظ مقدار پس از reload را بررسی می‌کنند. در حالت دادهٔ خراب، فایل پروژه همچنان قابل دانلود است و تاریخچهٔ خراب
بدون تصمیم کاربر پاک یا بازنویسی نمی‌شود. این‌ها آزمون مرورگر با خطای مصنوعی‌اند، نه پرکردن واقعی دیسک یا قطع برق ویندوز.
مجموع سناریوهای Chromium اکنون ده تست است؛ همه محلی موفق بوده‌اند و تحت اسکریپت CI مرورگر اجرا می‌شوند.

مسیر تحویل فایل اکنون از محدودهٔ دقیق بافر ورودی یک snapshot مستقل می‌گیرد و به writer هم کپی جدا می‌دهد؛
تغییر بافر توسط فراخواننده یا writer ناموفق، بایت‌های تلاش دوباره را تغییر نمی‌دهد. تست واحد، subarray و دو تلاش دوباره
پس از تغییر هر دو بافر را پوشش می‌دهد. هزینهٔ این جداسازی، کپی‌های موقت متناسب با اندازهٔ خروجی است؛ ذخیرهٔ مقصد همچنان اتمیک نیست.

کنترل عددی و اسلایدر، واحد نمایان خود را با `aria-describedby` معرفی می‌کنند؛ نام کنترل ثابت می‌ماند.
ناوبری بخش‌ها، ورودی‌های عددی، اسلایدر و summary تاریخچه نشانگر صریح `:focus-visible` دارند.
تست یازدهم Chromium، فوکوس صفحه‌کلیدی و outline سه‌پیکسلی ناوبری/ورودی/اسلایدر و توضیح دسترس‌پذیر mm و % را می‌سنجد؛
این بررسی جایگزین ممیزی کنتراست یا آزمون با screen reader واقعی نیست.

زمان‌بند نمایشگر با `visibilitychange` هنگام پنهان‌شدن سند متوقف و فریم معلق لغو می‌شود؛
بازگشت به صفحه یک فریم تازه درخواست می‌کند تا آخرین هندسه نمایش داده شود. callback لغوشدهٔ قدیمی
نمی‌تواند فریم جدید را پاک یا دوباره فعال کند و listener هنگام unmount حذف می‌شود.
دو تست واحد توقف/بازگشت و callback قدیمی را پوشش می‌دهند؛ این آزمونِ زمان‌بند است، نه آزمون تعویض تب واقعی یا مصرف باتری.

تست دوازدهم Chromium اتصال واقعی listener پنهان‌شدن به رندر SwiftShader را بررسی می‌کند:
با override آزمایشی `document.hidden` و ارسال `visibilitychange`، تغییر سگمنت و اندازهٔ پنجره
در وضعیت پنهان draw جدید ایجاد نمی‌کند و بازگشت به وضعیت نمایان رسم را از سر می‌گیرد؛ مقدار سگمنت نیز حفظ می‌شود.
این سناریو رویداد و وضعیت را شبیه‌سازی می‌کند و ادعای آزمون تعویض تب واقعی سیستم‌عامل ندارد.

تست سیزدهم Chromium ورود پروژه را پوشش می‌دهد: فایل خراب و فایل بزرگ‌تر از ۲۵۶KiB بدون نمایش تأیید جایگزینی
رد می‌شوند و ویرایش جاری حفظ می‌شود؛ لغو تأیید فایل سالم نیز مقدارها را تغییر نمی‌دهد. انتخاب دوبارهٔ همان فایل
پس از لغو موفق است و خطای قبلی پاک می‌شود. منطق برنامه در این مرحله تغییر نکرده؛ پوشش یکپارچه افزوده شده است.

### بازنشانی دوربین

دکمهٔ «بازنشانی دوربین» در نمای سه‌بعدی، موقعیت و هدف اولیهٔ دوربین را بدون تغییر پارامترها یا بازسازی مش
بازیابی می‌کند. حرکت باقی‌ماندهٔ damping پیش از بازنشانی تخلیه می‌شود. این دکمه با Enter هم کار می‌کند.
تست چهاردهم Chromium تصویر ناحیهٔ canvas را قبل از زوم و پس از بازنشانی در همان SwiftShader مقایسه می‌کند
و حفظ ضخامت و انقباض را می‌سنجد؛ این مقایسهٔ درون‌اجرایی است، نه مرجع تصویری بین GPUهای مختلف.

دکمهٔ «جا دادن مدل در نما» کرهٔ محاط‌کنندهٔ bounding box مش جاری را با حاشیهٔ ۱۵٪ در زاویهٔ کوچک‌تر افقی/عمودی
دوربین جا می‌دهد؛ جهت دید حفظ و مرکز هدف و صفحات near/far تنظیم می‌شوند. بازنشانی دوربین صفحات برش اولیه را هم برمی‌گرداند.
پنج تست واحد، قرارگیری گوشه‌های یک جعبهٔ جابه‌جاشده در کادر نماهای باریک/مربع/عریض و ورودی خالی/نامعتبر/نقطه‌ای را می‌سنجند.
تست مرورگر دکمه را با Enter فعال و بازگشت تصویری به نمای اولیه را پس از آن بررسی می‌کند؛ هندسه و واحدهای مدل تغییر نمی‌کنند.

### جست‌وجوی الگوها

کتابخانهٔ الگوها جست‌وجوی کاملاً محلی بر اساس نام فارسی، label انگلیسی و شناسه دارد. حروف ي/ی و ك/ک،
اعراب و تفاوت فاصله/نیم‌فاصله/خط تیره یکسان‌سازی می‌شوند؛ تمام واژه‌های پرس‌وجو باید در نام یا شناسه باشند.
فیلتر، الگوی انتخاب‌شده و اندازهٔ کاشی را تغییر نمی‌دهد؛ تعداد نتیجه اعلام و پاک‌کردن جست‌وجو همهٔ کارت‌ها را برمی‌گرداند.
چهار تست واحد و سناریوی پانزدهم Chromium جست‌وجو، نتیجهٔ خالی و حفظ انتخاب را می‌سنجند.

در تنظیمات نام‌دار، نام تکراری و سقف ۳۰ مورد پیام فارسی مشخص دارند؛ نام واردشده در خطا برای اصلاح باقی می‌ماند.
تست شانزدهم Chromium ذخیره و اعمال پس از reload، رد نام تکراری با فاصلهٔ ابتدا/انتها بدون تغییر بایت‌های کتابخانه،
لغو حذف و سپس تأیید حذف را پوشش می‌دهد. قابلیت جایگزینی نام تکراری اضافه نشده؛ رفتار امن قبلی حفظ شده است.

ترجیح حالت ساده/حرفه‌ای در کلید مستقل `patturn:editor-mode:v1` نگهداری و پس از reload بازیابی می‌شود؛
جزئی از فایل، هندسه یا تاریخچهٔ پروژه نیست. مقدار ناشناخته به حالت ساده برمی‌گردد و هنگام mount بازنویسی نمی‌شود.
اگر دسترسی یا نوشتن storage خطا دهد، تغییر حالت در نشست جاری فعال می‌ماند و پیام مخصوص ترجیح رابط نشان داده می‌شود.
شش تست واحد، دادهٔ نامعتبر/خواندن مسدود/نوشتن ناموفق و رفع خطا، و تست هفدهم Chromium ماندگاری هر دو حالت را پوشش می‌دهند.

کنترل‌های دوربین در گروه نام‌دار، دکمه‌های «نزدیک‌تر» و «دورتر» هم دارند؛ هر بار فاصله نسبت به هدف فعلی
در ۰٫۸ یا ۱٫۲۵ ضرب و بین دوبرابر near و نصف far محدود می‌شود. این تغییر، زوم دوربین است نه مقیاس هندسه.
دکمه‌ها با Enter کار می‌کنند و در عرض محدود می‌شکنند. تست هجدهم Chromium تغییر تصویری هر جهت،
بازگشت تصویری پس از reset و حفظ ضخامت پروژه را در همان اجرای SwiftShader بررسی می‌کند.

گزارش bundle اکنون `schemaVersion: 1` و وضعیت بودجهٔ خام ۶۰۰٬۰۰۰ بایت برای ادیتور همراه نمایشگر دارد؛
`enforcing: false` یعنی عبور از بودجه فعلاً CI را قرمز نمی‌کند، نه اینکه هدف محقق شده باشد.
ساخت این مرحله: entry خام ۳۵۲٬۵۶۰ بایت؛ ادیتور+نمایشگر خام ۸۵۷٬۵۷۶ و gzip برابر ۲۴۰٬۷۸۴ بایت؛ بودجه محقق نشده است.
پنج تست Node مسیرهای مشترک، چرخه، فایل تکراری و وابستگی مفقود را بررسی می‌کنند. گزارش JSON در workflow
به artifact چهارده‌روزهٔ `web-bundle-report` متصل شده؛ موفقیت اجرای جدید CI هنوز تأیید نشده است.
PDF/فونت اختیاری، WASM، worker و دارایی‌های غیر-JS در این معیار نیستند؛ این گزارش زمان بارگذاری یا LCP نیست.

بوم کامل ۳۰۰×۳۰۰ الگو اکنون هنگام اولین نمایش تخت یا خروجی SVG/DXF/ZIP ساخته و برای همان نوع الگو و اندازهٔ کاشی
بازاستفاده می‌شود؛ شروع در بخش فرم این محاسبه را انجام نمی‌دهد. تغییر ورودی‌ها getter مستقل می‌سازد و لغو ZIP همچنان
به هویت ورودی الگو متصل است. سه تست واحد، ساخت تنبل/کش، برابری با خروجی قبلی و تلاش دوباره پس از خطا را پوشش می‌دهند.
این بهینه‌سازی حذف محاسبهٔ بی‌مصرف است، نه کاهش حجم JS یا اثبات LCP؛ گزارش فعلی ادیتور+نمایشگر ۸۵۷٬۶۵۶ بایت خام است.

لغو ZIP علاوه بر هندسه/الگو، به ضخامت محاسبهٔ ظرفیت و سطح پرشدگی هم متصل است؛ پس از پایان await ساخت PDF
اگر درخواست لغو شده باشد، تولید SVG/DXF و ZIP ادامه پیدا نمی‌کند و پیام لغو مشخص نمایش داده می‌شود.
تست نوزدهم Chromium بارگذاری chunk PDF را نگه می‌دارد، ضخامت را هنگام بسته‌بندی تغییر می‌دهد، نبود دانلود قدیمی
را بررسی و سپس ZIP تلاش جدید را باز می‌کند تا wallMm جدید را تأیید کند. صادرکنندهٔ PDF اکنون signal را قبل و بعد از بارگذاری و بین صفحه‌ها بررسی می‌کند.


لغو PDF تعاونی است: در مسیر ZIP، قبل از import موتور/فونت، پس از import و بین صفحه‌ها بررسی می‌شود؛
بین صفحه‌ها به event loop فرصت داده می‌شود. import در حال اجرا و عملیات هم‌زمان یک صفحه قابل قطع فوری نیستند.
در لغو هیچ بایت PDF جزئی برگردانده نمی‌شود. سه تست واحد، لغو از قبل، لغو هنگام yield و ثابت‌ماندن بایت‌ها با signal فعال را می‌سنجند.

خروجی مستقل PDF نیز controller جدا و دکمهٔ «لغو آماده‌سازی PDF» دارد؛ تغییر پروفیل، تعداد قطعات، سگمنت، ضخامت،
انقباض یا پرشدگی درخواست جاری را لغو می‌کند. تغییر صرف تب‌ها آن را لغو نمی‌کند. پیام لغو/خطا در صفحه باقی می‌ماند
و تلاش جدید پیام قبلی را پاک می‌کند. تست بیستم Chromium بارگذاری موتور را معلق و لغو صریح، نبود دانلود قبلی
و موفقیت PDF تلاش بعدی را بررسی می‌کند. لغو پس از ارسال فایل به مسیر تحویل/دانلود دیگر تحت کنترل تولیدکننده نیست.

PDF پیش از اولین await از نقاط پروفیل، گزینه‌های سند و ردیف‌های پارامتر snapshot مستقل می‌گیرد؛ تغییر آرایه یا اشیای
فراخواننده هنگام بارگذاری/تولید صفحات، چیدمان و محتوای سند را ناسازگار نمی‌کند. تست D9 تغییر هم‌زمان نقاط، طول آرایه،
ردیف‌ها و نام پروژه را انجام می‌دهد و برابری دقیق نام و بایت‌ها با ورودی اولیه را می‌سنجد. AbortSignal عمداً مشترک باقی می‌ماند.

حدود ورودی PDF: حداکثر ۱۰٬۰۰۰ نقطه، قدرمطلق مختصات تا ۱۰٬۰۰۰٬۰۰۰mm و همان سقف قبلی ۱۰۰ کاشی.
تعداد نقاط پیش از کپی‌کردن payload بررسی و بیشینهٔ شعاع بدون spread محاسبه می‌شود. سه تست جدید حد مجاز،
رد اندازهٔ بیشتر پیش از خواندن نقاط و مختصات بزرگِ متناهی (از جمله پروفیل کوچک با انتقال بسیار بزرگ) را پوشش می‌دهند.
این سقف‌ها حفاظ محاسباتی‌اند، نه تضمین کارایی روی همهٔ دستگاه‌ها یا مجوز ساخت ابعاد بسیار بزرگ.

صادرکنندهٔ ZIP، نام پروژه و بایت‌های فایل‌های جانبی را پیش از فشرده‌سازی مستقل می‌کند؛ تغییر ورودی فراخواننده
هنگام فشرده‌سازی، نام فایل نهایی را با manifest ناسازگار نمی‌کند و backing buffer فایل جانبی نیز متعلق به فراخواننده می‌ماند.
تست آرشیو با زیرآرایهٔ ۳۰۰٬۰۰۰ بایتی، تغییر بافر/مسیر/نام پس از شروع و بازکردن ZIP این قرارداد را بررسی می‌کند.
این جداسازی هزینهٔ حافظهٔ موقت به اندازهٔ مجموع فایل‌های جانبی دارد؛ مش‌ها و خروجی‌های تولیدشده همچنان پیش از فشرده‌سازی تبدیل می‌شوند.

ZIP مسیرهایی را که در آن یک فایل هم‌زمان والد مسیر دیگری باشد رد می‌کند (مثلاً `notes.txt` و `notes.txt/info.txt`).
این بررسی در هر دو ترتیب، با NFC و حروف کوچک و برای نام‌های رزروشدهٔ README/manifest هم انجام می‌شود.
هفت تست برخورد فایل/پوشه، اختلاف حروف/Unicode و مجازبودن پوشهٔ مشترک یا پیشوند صرف را پوشش می‌دهند؛
این تست آرشیو است، نه آزمون استخراج در همهٔ فایل‌سیستم‌ها یا نسخهٔ نصب‌شدهٔ ویندوز.

حدود بستهٔ ZIP: حداکثر ۵۱۲ فایل شامل README و manifest، هر فایل ۶۴MiB و مجموع ورودی غیرفشرده ۲۵۶MiB.
فایل جانبی پیش از کپی بررسی می‌شود؛ فایل تولیدی پس از تبدیل و پیش از افزودن به آرشیو بررسی می‌شود (پس این سقف جلوی
همهٔ تخصیص‌های تبدیل هندسه را نمی‌گیرد). بودجه اندازهٔ غیرفشرده است، نه سقف peak حافظه، worker یا حجم ZIP نهایی.
هشت تست جدید حد دقیق، عبور یک‌بایتی، فایل خالی، اندازهٔ نامعتبر و احتساب فایل‌های تولیدی را می‌سنجند؛
برای آزمون بودجهٔ بایت از شمارنده استفاده شده و تخصیص ۲۵۶MiB در تست لازم نیست.

کنترل دوربین دکمه‌های چرخش چپ/راست هم دارد: هر بار چرخش افقی ۱۵ درجه حول محور عمودی جهانی و هدف فعلی،
بدون چرخاندن خود مش یا تغییر خروجی فایل. تست تصویری کنترل‌های صفحه‌کلید، هر دو جهت چرخش را نیز فعال می‌کند و
پس از هر بار بازنشانی، برابری تصویر با نمای اولیه را می‌سنجد. چرخش عمودی نیز با دکمه‌های «دید بالاتر/پایین‌تر» اضافه شده؛ جابه‌جایی هدف با دکمه هنوز اضافه نشده است.


دید بالاتر/پایین‌تر با گام ۱۵ درجه و محدودسازی زاویهٔ قطبی در فاصلهٔ ۰٫۰۱ رادیان از قطب‌ها کار می‌کند.
چرخش خالص فاصله را تغییر نمی‌دهد (محدودسازی فاصله فقط هنگام زوم اجرا می‌شود). چهار تست واحد، حفظ فاصله،
تغییرنکردن بردار ورودی، حرکت معکوس و تکرار حرکت نزدیک قطب‌ها را بررسی می‌کنند؛ تست تصویری هر شش حرکت دوربین را پوشش می‌دهد.

فهرست تنظیمات نام‌دار با رویداد `storage` برای کلید کتابخانه و پاک‌شدن storage در تب دیگر بازخوانی می‌شود؛
listener هنگام بسته‌شدن جزء حذف می‌شود و هیچ تنظیمی خودکار روی پروژه اعمال نمی‌شود. تست بیست‌ویکم Chromium
دو تب واقعی در یک context باز می‌کند و انتشار ذخیره/حذف و مستقل‌ماندن اندازهٔ کاشی هر پروژه را می‌سنجد.
این همگام‌سازی فهرست است، نه ویرایش مشارکتی یا تراکنش چندتب؛ پروژه و تاریخچهٔ خودکار بین تب‌ها ادغام نمی‌شوند.

تست بیست‌ودوم Chromium با getter مسدودشدهٔ localStorage و SecurityError مصنوعی شروع برنامه را بررسی می‌کند:
ویرایش و دانلود فایل پروژه (با بازکردن gzip و تأیید state) باقی می‌مانند؛ پس از رفع محدودیت، تلاش دوباره مقدار جاری
را ذخیره و تغییر مجدد حالت رابط، هشدار ترجیح را پاک می‌کند. هیچ pageerror ثبت نمی‌شود.
این آزمون خطای مصنوعی API است، نه تست تمام سیاست‌های حریم خصوصی یا محیط‌های WebView ویندوز.

تنظیمات نام‌دار الگو دکمهٔ «تغییر نام» دارند. لغو prompt تغییری نمی‌دهد؛ نام جدید پس از trim اعتبارسنجی و
در همان جای فهرست با حفظ نوع الگو و اندازهٔ کاشی، با یک setItem ذخیره می‌شود. نام تکراری، خالی، بلند یا مورد حذف‌شده رد می‌شود؛
نام نرمال‌شدهٔ بدون تغییر نوشتن ندارد و خطای ذخیره، دادهٔ قبلی را حفظ می‌کند. چهار تست واحد و تست بیست‌وسوم Chromium
لغو، تغییر نام، ماندگاری پس از reload و اعمال مقادیر قبلی را پوشش می‌دهند. این عملیات تراکنش هم‌زمان چندتب نیست.

دکمهٔ «به‌روزرسانی با مقادیر فعلی» پس از تأیید، نوع الگو و اندازهٔ کاشی جاری را در همان تنظیمات نام‌دار ذخیره می‌کند؛
نام و ترتیب فهرست حفظ می‌شوند. لغو بی‌اثر است؛ مورد حذف‌شده یا مقادیر نامعتبر رد و خطای نوشتن بدون حذف قبلی گزارش می‌شود.
اگر مقادیر یکسان باشند نوشتنی انجام نمی‌شود. سه تست واحد و سناریوی بیست‌وچهارم Chromium تأیید/لغو و بازیابی مقادیر جدید
پس از reload را پوشش می‌دهند. این عملیات همان ذخیرهٔ محلی تک‌نوشتنی است، نه تراکنش چندتب.

«دانلود پشتیبان کتابخانهٔ الگو» همهٔ موارد نام‌دار را در JSON با `format: patturn-pattern-library` و `version: 1`
ذخیره می‌کند، نه فقط تنظیمات فعال. دادهٔ ذخیره‌شده پیش از خروجی اعتبارسنجی می‌شود؛ کتابخانهٔ خراب به‌عنوان پشتیبان موفق صادر نمی‌شود.
فایل از همان مسیر تحویل مرورگر/دسکتاپ و تلاش دوبارهٔ خروجی عبور می‌کند. دو تست واحد و تست بیست‌وپنجم Chromium
ساختار و محتوای فارسی چند مورد و حفظ پروژهٔ جاری را پوشش می‌دهند. ورود ادغامی این JSON اکنون با اعتبارسنجی و تأیید کاربر فعال است.


ورود پشتیبان کتابخانه حداکثر ۶۴KiB، UTF-8 معتبر، format/version و فیلدهای سخت‌گیرانه دارد. پس از پیش‌نمایش تعداد
و تأیید، فقط موارد جدید افزوده می‌شوند؛ موارد کاملاً یکسان نوشتن یا تکرار ندارند. نام یکسان با مقادیر متفاوت، نام تکراری
در خود فایل، الگوی ناشناخته، دادهٔ خراب یا عبور مجموع از ۳۰ مورد، کل ورود را بدون تغییر قبلی رد می‌کند.
هنگام ثبت، storage دوباره خوانده و بررسی می‌شود؛ این بررسی تراکنش هم‌زمان چندتب نیست. پروژهٔ باز خودکار اعمال نمی‌شود.
چهار تست واحد و تست بیست‌وششم Chromium لغو/تأیید، تکرار، تعارض و حفظ پروژه را پوشش می‌دهند؛ انتخاب فایل در WebView نصب‌شدهٔ ویندوز هنوز عملی تست نشده است.

با خروج از بخش الگو، توکن ورود پشتیبان باطل می‌شود؛ نتیجه یا خطای دیررس File.arrayBuffer دیگر پنجرهٔ تأیید باز نمی‌کند،
داده نمی‌نویسد و وضعیت جزء بسته‌شده را تغییر نمی‌دهد. تست بیست‌وهفتم Chromium خواندن فایل را نگه می‌دارد، بخش را می‌بندد،
سپس خواندن را آزاد و پایان آن را مشاهده می‌کند تا نبود prompt/نوشتن را بررسی کند. خود I/O فایل قابل قطع فوری نیست.

دکمهٔ «لغو خواندن پشتیبان» بدون خروج از بخش، درخواست را بی‌اعتبار و انتخاب فایل جدید را ممکن می‌کند؛
پس از ورود موفق نیز تعداد موارد واقعاً افزوده‌شده اعلام می‌شود. تست بیست‌وهشتم Chromium یک خواندن معلق را لغو،
پشتیبان دیگری را وارد و سپس نتیجهٔ قدیمی را آزاد می‌کند تا فقط یک تأیید و فقط مورد جدید در کتابخانه باقی بماند.
لغو، I/O فایل را قطع نمی‌کند و فقط اثر نتیجهٔ آن بر برنامه را حذف می‌کند.

تاریخچهٔ پارامترها در پایان گروهی که دقیقاً به snapshot آغازش برگشته باشد، گام بی‌اثر را حذف می‌کند؛ شروع تکراری
همان گروه نیز گام تازه نمی‌سازد. سه تست واحد و تست بیست‌ونهم Chromium حرکت اسلایدرِ رفت‌وبرگشت و باقی‌ماندن
واگردِ ویرایش‌های معنی‌دار را پوشش می‌دهند. در گروه بدون تغییر نهایی، شاخهٔ redo و قدیمی‌ترین گام جابه‌جاشده در سقف تاریخچه نیز به وضعیت پیش از گروه برمی‌گردند.


تاریخچه تا پایان هر گروه snapshot ساختاریِ آرایه و cursor آغاز را نگه می‌دارد؛ در بازگشت کامل به مقدار آغاز، همان تاریخچه
بازیابی می‌شود، اما تغییر واقعی همچنان شاخهٔ redo را کنار می‌گذارد. سه تست واحد و تست سی‌ام Chromium حفظ redo پس از
اسلایدر رفت‌وبرگشت، حفظ قدیمی‌ترین گام در سقف ظرفیت و رفتار تغییر واقعی را پوشش می‌دهند. این تاریخچه فقط در حافظه است.

نه تست مرزی، مبدأ غیرصفر/منفی، گام اعشاری، سقف غیرهم‌تراز و پایداری نرمال‌سازی دوباره را پوشش می‌دهند. قرارداد داخلی مانند کنترل‌های HTML به بازهٔ مرتب و گام مثبت نیاز دارد؛ دقت گردکردن همچنان هشت رقم اعشار است.

تست سی‌وششم Chromium اصلاح سقف، ورودی خالی، پاک‌شدن پیام و نساختن گام تاریخچهٔ اضافی را می‌سنجد؛ خروجی صوتی صفحه‌خوان واقعی هنوز آزمایش نشده است.

پیام اصلاح عددی با تغییر خارجی مقدار (از جمله واگرد) منقضی می‌شود، نه فقط پنهان؛ ازنو به همان عدد، پیام تعامل قبلی را احیا نمی‌کند.
یک تست واحد و گسترش سناریوی مرورگر این چرخه را پوشش می‌دهند و باقی‌ماندن پیام تازه هنگام اعمال مقدار اصلاح‌شده را نیز بررسی می‌کنند.

عنوان واگرد و ازنو برای تغییر فرم، نام فارسی سه فرم را به‌جای شناسهٔ داخلی نمایش می‌دهد.
سه آزمون واحد و تست سی‌وهفتم Chromium عنوان، tooltip و بازیابی صحیح شناسهٔ فرم را بررسی می‌کنند؛ قالب فایل پروژه تغییر نکرده است.

نام فارسی الگوها برای کارت‌ها، جست‌وجو و عنوان واگرد/ازنو از PATTERN_NAMES_FA در config خوانده می‌شود؛ شناسه‌های ذخیره‌شده تغییر نمی‌کنند.
آزمون هم‌پوشانی دقیق نام‌ها با همهٔ الگوهای داخلی، چرخهٔ تاریخچه برای یازده مقصد دیگر، fallback شناسهٔ ناشناخته و تست سی‌وهشتم Chromium این مسیر را پوشش می‌دهند.

فهرست تنظیمات نام‌دار، کنار نام هر مورد نوع الگو را از نام‌نامهٔ مشترک فارسی و اندازهٔ کاشی را با رقم فارسی و واحد میلی‌متر نمایش می‌دهد.
تست سی‌ونهم Chromium دو تنظیمات هم‌اندازه از الگوهای متفاوت را ذخیره و پس از reload از روی خلاصه تفکیک می‌کند و اعمال هر کدام را می‌سنجد. ساختار ذخیره‌سازی تغییر نکرده است.

جست‌وجوی تنظیمات ذخیره‌شده بر نام تنظیمات، نام فارسی نوع الگو و شناسهٔ آن اعمال می‌شود؛ همهٔ واژه‌ها باید تطبیق داشته باشند.
نرمال‌سازی مشترک با جست‌وجوی الگو، حروف عربی/فارسی و اعراب و فاصله‌ها را همسان می‌کند. فیلتر فقط نمای فهرست است و در پروژه، فایل پشتیبان و دادهٔ ذخیره‌شده تغییری نمی‌دهد؛ با بستن بخش و بازنصب مؤلفه بازنشانی می‌شود.
تست چهلم Chromium تطبیق حروف عربی، نام نوع، نتیجهٔ خالی، پاک‌کردن و حفظ دو مورد پس از reload را می‌سنجد.

دکمهٔ پاک‌کردن جست‌وجو در کتابخانهٔ الگو و تنظیمات ذخیره‌شده، فوکوس را به کادر همان جست‌وجو برمی‌گرداند؛ حذف دکمه از DOM دیگر فوکوس را رها نمی‌کند.
تست چهل‌ویکم Chromium فعال‌سازی دکمه با Enter و تایپ بلافاصله پس از آن را می‌سنجد؛ تست جست‌وجوی تنظیمات نیز فوکوس پس از پاک‌کردن را بررسی می‌کند.

راهنمای پشتیبان کتابخانه تصریح می‌کند که جست‌وجو دامنهٔ خروجی را محدود نمی‌کند.
تست چهل‌ودوم Chromium با فیلتر فعال، فایل JSON واقعی دانلودشده را می‌خواند و وجود هر دو مورد آشکار و پنهان با مقادیر کامل، حفظ فیلتر و انتخاب پروژه و باقی‌ماندن همهٔ موارد در کتابخانه را بررسی می‌کند.

کتابخانهٔ الگو با React.memo و callback ثابت انتخاب، در رندرهای نامرتبط والد دوباره ارزیابی نمی‌شود.
آزمون واحد، ثابت‌ماندن props خروجی در رندر والد با ورودی یکسان و تازه‌شدن انتخاب، callback و جست‌وجوی محلی را می‌سنجد. این بهینه‌سازی اندازه‌گیری LCP، کاهش اندازهٔ بسته یا بنچمارک سرعت نیست و مورد عملکرد در چک‌لیست باز می‌ماند.

پیش‌نمایش تخت نیز memo شده است: با آرایهٔ مسیرهای کش‌شده و ضخامت خط ثابت، رندر والد مسیرهای SVG را دوباره map نمی‌کند.
آزمون واحد ثابت‌ماندن خروجی با props یکسان و به‌روزرسانی مسیرها، fill و ضخامت را بررسی می‌کند. مسیرها باید مانند خروجی createPatternCanvas پس از ساخت تغییرناپذیر تلقی شوند؛ این تغییر ادعای سنجش سرعت، LCP یا کاهش اندازهٔ بسته ندارد.

اگر جست‌وجوی کتابخانه کارت الگوی فعال را پنهان کند، نام فارسی انتخاب فعال و دکمهٔ «نمایش الگوی فعال» ظاهر می‌شود.
دکمه فقط جست‌وجو را خالی و فوکوس را به کادر آن برمی‌گرداند. تست چهل‌وسوم Chromium فعال‌سازی با Enter، حفظ انتخاب و عنوان تاریخچه و نبود گام واگرد اضافی را بررسی می‌کند.

حذف یا تغییر نام موفق تنظیمات ذخیره‌شده، فوکوس را به کادر جست‌وجوی فهرست می‌برد تا حذف ردیف قبلی مسیر صفحه‌کلید را قطع نکند؛ لغو یا خطا انتقال فوکوس برنامه‌ای ندارد.
تست چهل‌وچهارم Chromium مسیرهای لغو و تأیید هر دو عملیات را با Enter می‌سنجد و حفظ تعداد موارد و انتخاب پروژه هنگام لغو را بررسی می‌کند.

نرمال‌سازی مشترک جست‌وجو، ارقام فارسی و عربی را فقط برای تطبیق به لاتین تبدیل می‌کند؛ نام ذخیره‌شده و نام صادرشده در پشتیبان دست‌نخورده می‌مانند.
هفت آزمون واحد تمام رقم‌ها، ترکیب سه نوع رقم و پایداری نرمال‌سازی را می‌سنجند؛ تست چهل‌وپنجم Chromium جست‌وجوی نام‌های شماره‌دار با هر سه نوع رقم و حفظ نام پس از reload را بررسی می‌کند.

پس از خطای تحویل فایل، دکمهٔ «کنارگذاشتن خروجی ناموفق» ارجاع به بایت‌های نگه‌داشته‌شده برای retry را حذف می‌کند و پیام فارسی نیاز به ساخت خروجی تازه نشان می‌دهد؛ تنظیمات پروژه تغییر نمی‌کند.
دو تست واحد، بی‌اثرشدن retry پس از کنارگذاشتن، موفقیت خروجی تازه و حفظ قفل نوشتن در حال اجرا را می‌سنجند. این قابلیت فایل مقصد احتمالی/ناقص را پاک نمی‌کند، I/O را قطع نمی‌کند و تضمین بازگشت فوری حافظه به سیستم‌عامل نیست؛ مسیر خطای بومی ویندوز هنوز عملی آزمایش نشده است.

تست چهل‌وششم Chromium خطای ساخت Object URL در تحویل مرورگری را تزریق می‌کند؛ پیام خطا و دکمهٔ retry، کنارگذاشتن از رابط واقعی، حفظ پارامتر و عنوان تاریخچه و دانلود SVG تازه را بررسی می‌کند.
این سناریو خطای فایل‌سیستم یا پنجرهٔ ذخیرهٔ بومی ویندوز نیست و موفقیت مرورگر همچنان فقط درخواست دانلود را گزارش می‌کند.

تحویل مرورگری در requestBrowserDownload جدا شده است؛ Object URL در خطای تنظیم لینک یا کلیک فوراً آزاد می‌شود و در مسیر عادی با همان مهلت یک‌ثانیه‌ای قبلی آزاد می‌شود.
چهار تست واحد با ساعت مصنوعی، snapshot بایت‌ها، URL دقیق، زمان آزادسازی، خطای کلیک/تنظیم لینک و شکست پیش از ساخت URL را پوشش می‌دهند. آزادسازی URL به معنی تأیید ذخیره روی دیسک یا بازگشت فوری حافظه به سیستم‌عامل نیست.

مالک تحویل فایل پس از unmount، دادهٔ retry قبلی را رها می‌کند و نتیجه/خطای دیررس writer را به وضعیت رابط یا retry تبدیل نمی‌کند؛ فراخوانی توابع باقی‌ماندهٔ آن مالک نیز نوشتن تازه‌ای آغاز نمی‌کند.
سه تست واحد موفقیت دیررس، شکست دیررس و پاک‌شدن retry قبلی را بررسی می‌کنند. نوشتن بومی در حال اجرا لغو نمی‌شود و ممکن است پس از بسته‌شدن رابط به پایان برسد؛ این حفاظت تضمین توقف I/O یا بازگشت فوری حافظه نیست.

تست چهل‌وهفتم Chromium خطای کلیک دانلود پس از ساخت Blob URL را تزریق و آزادشدن URL دقیق را ثبت می‌کند؛ پس از تغییر انتخاب الگو، retry باید بایت‌های snapshot قبلی را دانلود کند، نه خروجی پروژهٔ تازه را.
آزمون همچنین آزادشدن URL مسیر موفق پس از مهلت را با انتظار شرطی و بدون sleep ثابت بررسی می‌کند. این ثبت API مرورگر است، نه اندازه‌گیری مصرف حافظه یا آزمون دیسک بومی ویندوز.

fallback فیزیکی KeyZ/KeyY فقط برای مقدار key تک‌نویسه‌ای و غیر از حروف لاتین A–Z فعال است؛ حروف لاتین دیگر به واگرد/ازنو تبدیل نمی‌شوند و Dead/Process/Unidentified نادیده می‌مانند. Z/Y معنایی همچنان مقدم هستند.
هشت مورد واحد و تست چهل‌وهشتم Chromium، تداخل چیدمان لاتین و کلیدهای ترکیبی ویژه و باقی‌ماندن پشتیبانی key فارسی را بررسی می‌کنند؛ تعویض واقعی چیدمان سیستم‌عامل در این تست انجام نمی‌شود.

Blob دانلود مرورگری براساس پسوند شناخته‌شده MIME متناسب دارد: SVG، PDF، JSON، ZIP، STL، OBJ و DXF. پسوند ناشناخته و فایل پروژه همچنان application/octet-stream هستند.
دوازده مورد واحد حروف بزرگ، چندپسوندی و نام ناشناخته را پوشش می‌دهند؛ سناریوی موجود retry مرورگر نیز نوع image/svg+xml و برابری بایت‌ها را بررسی می‌کند. این فراداده به معنی تغییر فرمت فایل، تشخیص محتوا یا تضمین پشتیبانی برنامه‌های CAD نیست.

شکست همگام کپی اولیهٔ بایت‌های تحویل فایل، پیام فارسیِ «آماده‌سازی ناموفق/ذخیره آغاز نشد» می‌دهد؛ retryable=false مانع نمایش تلاش مجدد بدون snapshot می‌شود و retry قدیمی نیز کنار گذاشته می‌شود.
دو تست واحد خطای slice تزریق‌شده، شروع‌نشدن writer، نبود retry اشتباه و امکان خروجی تازه را بررسی می‌کنند. این سناریو تضمین بازیابی از OOM کشندهٔ موتور JavaScript نیست؛ فقط استثنای قابل‌گرفتن را پوشش می‌دهد.

شکست کپی ثانویهٔ snapshot برای writer از خطای پس از ورود به writer تفکیک می‌شود: قبل از فراخوانی writer پیام «ذخیره آغاز نشد» و حفظ خروجی برای retry نمایش داده می‌شود؛ هشدار فایل مقصد احتمالیِ ناقص فقط پس از شروع writer باقی است.
یک آزمون واحد شکست کپی دوم را تزریق می‌کند و شروع‌نشدن writer، آزادشدن قفل و موفقیت retry همان بایت‌ها را می‌سنجد؛ این آزمون کمبود واقعی حافظه را ایجاد نمی‌کند.

retry از snapshot تحت مالکیت موجود استفاده می‌کند و تنها کپی تحویل به writer را می‌سازد؛ کپی مجدد برای نگهداری حذف شده است.
اگر کپی تحویل هنگام retry استثنا بدهد، snapshot از دست نمی‌رود و تلاش بعدی ممکن است. تست واحد تعداد یک slice در هر retry، شکست کپی و موفقیت تلاش بعدی با همان بایت‌ها را بررسی می‌کند؛ این کاهش یک کپی است، نه اندازه‌گیری اوج حافظهٔ کل فرایند.

هر تنظیم ذخیره‌شده که نوع الگو و اندازهٔ کاشی آن دقیقاً با پروژه یکی باشد، نشان «مطابق تنظیمات فعلی» دارد؛ ممکن است چند نام هم‌زمان مطابق باشند.
این نشانگر شناسهٔ انتخاب ذخیره‌شده یا نشانهٔ ذخیره‌شدن کل پروژه نیست و خودکار چیزی اعمال نمی‌کند. تست چهل‌ونهم Chromium تطابق چند مورد، تفاوت نوع/اندازه و به‌روزرسانی با اعمال و واگرد/ازنو را بررسی می‌کند.

«اعمال» تنظیمات نام‌دار، هنگام کلیک دوباره کتابخانه را می‌خواند و اعتبارسنجی می‌کند؛ مقادیر قدیمیِ ردیف نمایش‌داده‌شده مرجع اعمال نیستند.
تست پنجاهم Chromium با تغییر ذخیره بدون storage event، اعمال نسخهٔ تازه و به‌روزرسانی ردیف را می‌سنجد؛ حذف بعدی باید خطای فارسی بدهد و پارامتر و عنوان تاریخچه را حفظ کند. این بازخوانی، تراکنش میان تب‌ها یا قفل سراسری localStorage نیست.

حذف نام غایب در کتابخانه idempotent و بدون setItem است؛ حذف از ذخیرهٔ غایب سند خالی ایجاد نمی‌کند و حذف تکراری قالب و بایت‌های باقی‌مانده را بازنویسی نمی‌کند.
سه آزمون واحد ذخیرهٔ غایب، حذف تکراری با نویسندهٔ خطادار و شکست حذف واقعی با حفظ داده را می‌سنجند. دادهٔ خراب همچنان پیش از تشخیص no-op رد می‌شود؛ این رفتار قفل یا تراکنش بین تب‌ها نیست.

کتابخانهٔ بدون مورد، راهنمای ساخت اولین تنظیم یا ورود پشتیبان دارد؛ نتیجهٔ صفر جست‌وجو پیام جداگانه دارد. هنگام خطای خواندن، هیچ‌یک به‌اشتباه خالی‌بودن کتابخانه را القا نمی‌کنند.
تست پنجاه‌ویکم Chromium حالت ابتدایی، ذخیرهٔ اولین مورد، فیلتر بی‌نتیجه، حذف آخرین مورد و دادهٔ خراب را در همین مسیر بررسی می‌کند.


### دروازهٔ lint در CI
Node پشتیبانی‌شده برای ابزارهای توسعه اکنون `^22.13.0 || ^24.0.0 || >=26.0.0` است (به‌علت حداقل نسخهٔ ESLint 10).
`npm run lint` همهٔ JS/TS/TSX سورس، تست و تنظیمات را با قواعد خطایابی اجرا می‌کند؛ node_modules و خروجی‌های تولیدی خارج‌اند. این دروازه قواعد فرمت‌بندی/Prettier یا تحلیل نوع‌محور و React Hooks نیست؛ بررسی نوع‌ها جدا با `npm run typecheck` انجام می‌شود.
Workflow کیفیت، lint را در job وب و ویندوز پیش از typecheck برای push/PRهای مرتبط با برنامه اجرا می‌کند. این اتصال به معنی فعال‌بودن branch protection در تنظیمات GitHub نیست.
سه تست Node پیکربندی lint، پذیرش TS/JSX، رد نمونه‌های معیوب و محدودهٔ فایل‌های ورودی/استثناها را بررسی می‌کنند.


### حریم خصوصی
سند فارسی [حریم خصوصی](docs/privacy.fa.txt) در بخش «حریم خصوصی و داده‌های محلی» داخل برنامه نیز از همان فایل محلی نمایش داده می‌شود؛ برای خواندن آن درخواست خارجی لازم نیست.
متن، دادهٔ ذخیره‌شده، تاریخچه/پشتیبان، اشتراک‌گذاری فایل، شبکهٔ نسخهٔ میزبانی‌شده، نبود رمزگذاری اختصاصی و حذف داده را توضیح می‌دهد و محدودیت آزمون نصب/آفلاین ویندوز را پنهان نمی‌کند. این اطلاعیه تضمین امنیت یا مشاورهٔ حقوقی نیست.
دو تست واحد یکسان‌بودن متن بسته‌بندی‌شده و پوشش موضوعات را می‌سنجند؛ تست پنجاه‌ودوم Chromium باز/بسته‌کردن با Enter و حفظ پارامتر و تاریخچه را بررسی می‌کند.


### نسخه‌بندی و تاریخچهٔ تغییرات
[تاریخچهٔ فارسی](CHANGELOG.fa.md) وضعیت نسخهٔ توسعه را با قابلیت‌ها و محدودیت‌ها ثبت می‌کند؛ وجود مدخل نسخه، اعلام انتشار عمومی نیست.
`npm run release:check` تطابق نسخهٔ SemVer ریشه، همهٔ workspaceها، package-lock، Tauri و بخش package در Cargo.toml و وجود یک مدخل فارسی همان نسخه را بررسی می‌کند. این فرمان در CI وب و ویندوز پیش از lint اجرا می‌شود؛ نسخهٔ فعلی بدون افزایش، 0.1.0 باقی مانده است.
برای تغییر نسخه، همهٔ این منابع و lock را هماهنگ و مدخل فارسی اضافه کنید. شش تست Node اعتبار نسخه و عدم تطابق/مدخل تکراری/نبود متن فارسی را پوشش می‌دهند. چک نسخه جایگزین آزمون نصب، امضا، انتشار Release یا تأیید محتوای همهٔ ادعاهای CHANGELOG نیست؛ Cargo.lock تولیدی در این بررسی خوانده نمی‌شود.


### حمایت اختیاری
بخش حمایت، اطلاعات صاحب کارت و تماس را فقط از AUTHOR می‌خواند؛ شماره گروه‌بندی‌شده و قابل‌انتخاب است و دکمهٔ کپی، فقط cardRaw را در کلیپ‌بورد می‌نویسد. در نبود API یا رد دسترسی، راهنمای کپی دستی نمایش داده می‌شود.
این بخش تراکنش بانکی، خرید پلن و فعال‌سازی کلید ندارد؛ باید نام گیرنده در برنامهٔ بانکی بررسی شود. چهار تست واحد و تست پنجاه‌وسوم Chromium موفقیت و خطای API شبیه‌سازی‌شده، Enter و حفظ پروژه/تاریخچه را می‌سنجند؛ پرداخت واقعی یا دسترسی کلیپ‌بورد در نسخهٔ نصب‌شدهٔ ویندوز تأیید نشده است.


### پروفایل محلی اختیاری
بخش «پروفایل محلی و تنظیمات نمایش نام» نام (تا ۸۰ نویسه)، ایمیل اختیاری معتبر (تا ۲۵۴ نویسه) و نمایش نام را فقط با ذخیرهٔ صریح در کلید مستقل `patturn:local-profile:v1` می‌نویسد. ورود، رمز، احراز هویت، تأیید ایمیل و سرور ندارد؛ برای استفاده از ابزارها لازم نیست.
دادهٔ خراب یا بیش از ۸۱۹۲ واحد متنی بازنویسی نمی‌شود؛ بازخوانی یا حذف صریح با تأیید مسیر بازیابی است. حذف فقط کلید پروفایل را پاک می‌کند و پروژه، تاریخچه، حالت کنترل‌ها و کتابخانه را تغییر نمی‌دهد. نسخهٔ نخست همگام‌سازی زندهٔ پروفایل بین تب‌ها ندارد؛ بازخوانی صریح دادهٔ تازه را می‌گیرد.
نام و ایمیل به فایل پروژه و خروجی ساخت اضافه نمی‌شوند و رمزگذاری اختصاصی ندارند. ۱۱ تست واحد محدودیت/خطا/حذف و دو تست مرورگر ذخیره و reload، خروجی پروژهٔ بدون اطلاعات شخصی، لغو/حذف و بازیابی دادهٔ خراب را می‌سنجند؛ ذخیره در WebView نصب‌شدهٔ ویندوز هنوز عملی تست نشده است.


### چاک‌ساز
در بخش خروجی، «چاک‌ساز — شیب ۲ درجه و سوراخ تخلیه» یک تکیه‌گاه حلقوی توپر تولید می‌کند: قطر پایه ۴۰–۲۰۰، ارتفاع ۱۰–۱۰۰ و قطر سوراخ عبوری ۴–۲۰ میلی‌متر، شیب بیرونی ثابت ۲ درجه رو به داخل. نمای SVG فقط مقطع شماتیک است، نه نمایش سه‌بعدی یا الگوی ساخت تخت.
هسته با چهار حلقهٔ مشترک و اتصال دوری، حجم بستهٔ genus-one می‌سازد؛ درپوش دیسکی روی سوراخ ندارد. خروجی STL با ۹۶ سگمنت، پیش از تحویل دوباره validateMesh می‌شود. ۲۷ ترکیب مرزی، هشت ورودی نامعتبر و یک آزمون قطعیت/تفکیک مش (مجموع ۳۶) بسته‌بودن، حجم مثبت و انطباق حجم با فرمول حلقوی مخروط ناقص را می‌سنجند. تست پنجاه‌وششم Chromium فایل STL واقعی را از نظر ابعاد، بایت‌ها و رأس‌های دور از محور بررسی می‌کند.
تنظیمات ابزار موقتی و مستقل از فرم، تاریخچه، فایل پروژه و ZIP قالب هستند و با خروج از بخش بازنشانی می‌شوند. این نسخه چاک چاپ‌شده/روی چرخ را آزمایش نکرده است؛ واترتایت‌بودن تأیید تحمل بار، تعادل، سرعت چرخ یا چسبندگی نیست و پیش از استفادهٔ عملی بررسی تخصصی لازم است.


### رینگ‌روندر
در بخش خروجی، رینگ‌روندر یک پلاگ توپر با شیب ۳ درجه می‌سازد؛ قطر اسمی دهانه (۲۰–۱۶۰mm) در نیمهٔ ارتفاع (۱۰–۱۰۰mm) قرار می‌گیرد. قطر پایه برابر D + H×tan(3°) و قطر سر باریک برابر D − H×tan(3°) است. نمای SVG صرفاً مقطع شماتیک است و خط نقطه‌چین محل قطر اسمی را نشان می‌دهد.
هسته از revolve بسته با دو درپوش مشترک استفاده می‌کند؛ خروجی STL با ۹۶ سگمنت دوباره اعتبارسنجی می‌شود. ۲۷ ترکیب قطر/ارتفاع/تفکیک، هشت ورودی نامعتبر و یک آزمون قطعیت (۳۶ مورد) حجم تحلیلی با تصحیح چندضلعی، شیب، تطابق قطر اسمی و بسته‌بودن را می‌سنجند. تست پنجاه‌وهفتم Chromium STL دانلودشده را برای قطر و ارتفاع و شیب بررسی می‌کند.
قطر مستقل از فرم اصلی است و انقباض، لقی، نوع گل و رفتار فیزیکی در آن لحاظ نشده‌اند. تنظیمات موقتی‌اند و با خروج از بخش بازنشانی می‌شوند؛ در فایل پروژه، تاریخچه یا ZIP قالب نیستند. آزمون چاپ، گیرکردن یا تحمل نیرو انجام نشده و خروجی تضمین ایمنی کاربردی ندارد.


### تقسیم افقی فرم
در بخش خروجی، «تقسیم افقی فرم در ارتفاع انتخابی» فرم بستهٔ فعلی را با صفحهٔ Y ثابت (mm) به پایین/بالا می‌بُرد و به هر قطعه درپوش تخت می‌دهد. مختصات اصلی حفظ می‌شوند؛ مدل دوباره مرکزدهی نمی‌شود. سطح برش کلید، فاصلهٔ اتصال یا جبران انقباض ندارد.
هسته ورودی بسته و متناهی، ارتفاع داخلی غیرمماس، خروجی غیرخالی، اعتبار دو مش و بقای مجموع حجم (تلورانس max(0.01mm³,0.01%)) را کنترل می‌کند و اشیای موقت WASM را آزاد می‌کند. ۱۲ تست واحد برش استوانه، حفظ سوراخ چاک، ارتفاع نامعتبر و مش خراب را می‌سنجند. دو سناریوی مرورگر (۵۹ تست کل) STL واقعی دو بخش، ابطال با تغییر ارتفاع، استقلال خطای WASM از فرم و بازیابی با تلاش صریح را بررسی می‌کنند.
ساخت CSG همگام پس از بارگذاری WASM اجرا می‌شود و در میانهٔ محاسبه قابل‌قطع نیست؛ هنگام انتظار بارگذاری، نتیجهٔ درخواست قدیمی پس از تغییر ورودی/بستن بخش اعمال نمی‌شود. تنظیمات و نتایج موقتی و خارج از فایل پروژه و ZIP قالب‌اند. نتیجه برای مش‌های بسته است؛ قطعه ممکن است چند مؤلفه داشته باشد و تعداد مؤلفه یا سهولت مونتاژ تضمین نمی‌شود. آزمون چاپ/اتصال واقعی هنوز انجام نشده است.


### الگوی پازل
در بخش خروجی، الگوی پازل شبکهٔ ۲ تا ۶ سطر/ستون، خانهٔ ۲۰ تا ۶۰mm، عمق پارامتری زبانه از ۱ تا یک‌ششم خانه و seed صحیح ۰ تا ۶۵۵۳۵ دارد. هر مرز داخلی فقط یک‌بار و با سه Bézier مکعبی رسم می‌شود؛ این خروجی شبکهٔ خطوط برش مشترک است، نه مجموعهٔ کانتورهای مستقل هر قطعه. عمق کنترل زبانه مقیاس پارامتری است و برخی کنترل‌های Bézier تا ۱٫۳ برابر آن فاصله می‌گیرند.
ورودی و seed یکسان خروجی یکسان می‌دهند و پیش‌نمایش همان مسیرهای SVG/DXF را مصرف می‌کند. تغییر اندازهٔ خانه، عمق زبانهٔ نامجاز را محدود می‌کند. SVG واحد واقعی و ضخامت نمایشی ۰٫۲mm دارد؛ DXF با تقریب مکعبی ۰٫۰۵mm پیش از clipping صادر می‌شود. ۳۷ آزمون الگو، سه بازخوانی مستقل DXF و تست شصتم Chromium تعداد مرزها، کنترل‌های داخل بوم، قطعیت، seed و فایل‌های واقعی را بررسی می‌کنند.
تنظیمات موقتی و مستقل از پروژه/ZIP هستند. جبران kerf، لقی، ضخامت و جنس ورق، آزمون عمومی عدم تقاطع و تضمین اتصال قطعات یا برش واقعی وجود ندارد؛ خروجی بدون کنترل در CAD و نمونه‌سازی برای تولید نهایی استفاده نشود.


### درخواست قابلیت محلی
بخش «درخواست قابلیت — فهرست خصوصی این دستگاه» تا ۳۰ پیشنهاد ۲۴۰نویسه‌ای را با شناسه، زمان ثبت و رأی محلی در `patturn:feature-requests:v1` نگه می‌دارد. هر کلیک رأی یک واحد (تا ۹۹۹۹) می‌افزاید؛ این شمارش محلی است و محدودیت یک رأی برای هر کاربر یا رأی‌گیری عمومی نیست.
Top براساس رأی و سپس زمان/شناسهٔ جدیدتر و New براساس زمان/شناسه مرتب می‌کند؛ ترتیب ذخیره تغییر نمی‌کند. خروجی JSON تمام موارد را بدون تغییر رأی‌ها نگه می‌دارد؛ برای رساندن پیشنهاد به سازنده باید فایل را خودتان جداگانه به اشتراک بگذارید. ورود JSON یا همگام‌سازی بین تب‌ها/سرور پیاده نشده است؛ بازخوانی صریح دادهٔ تازه را می‌گیرد. حذف فهرست از تنظیمات دادهٔ سایت ممکن است و مستقل از فایل صادرشده است.
دادهٔ خراب/بیش‌ازحد بدون بازنویسی رد می‌شود و خطای quota پروژه را متوقف نمی‌کند. شش آزمون ذخیره و دو تست مرورگر (۶۲ تست کل) ثبت، رأی، مرتب‌سازی، خروجی واقعی، reload، حفاظت داده خراب و استقلال پروژه را بررسی می‌کنند. این بخش وعدهٔ پذیرش پیشنهاد یا آزمون نصب‌شدهٔ ویندوز نیست.


### فوت‌رینگِ خروجی مستقل
در بخش خروجی، حلقهٔ پایه با عرض ۲–۱۲mm، عمق ۲–۱۵mm و سبک صاف/پخ/گرد به فرم فعلی union می‌شود. شعاع بیرونی حلقه ثابت و برابر ۸۵٪ شعاع پایهٔ نمونه‌برداری‌شده است؛ حلقه ۰٫۵mm با کف هم‌پوشانی دارد. ورودی باید فرم بستهٔ محورمتقارن با کف تخت حول Y باشد، نه مش دلخواه جابه‌جاشده.
مقطع حلقه بسته است؛ پخ از یک‌سوم حداقل عرض/عمق و گردی از دو ربع‌دایرهٔ شش‌بخشی ساخته می‌شود. اتصال بدون هم‌پوشانی یا حلقهٔ کاملاً مدفون رد می‌شود و نتیجه پیش از STL اعتبارسنجی می‌شود. ۳۶ تست حلقه، پنج تست CSG و تست شصت‌وسوم Chromium برای سه سبک، حجم/کران/قطعیت/مش معتبر و ابطال نتیجه با تغییر پارامتر را پوشش می‌دهند.
خروجی فوت‌رینگ‌دار جداست: فرم اصلی و ظرفیت و قالب تغییر نمی‌کنند؛ پارامتر و نتیجه در تاریخچه، فایل پروژه و ZIP نیستند و هنگام خروج از بخش بازنشانی می‌شوند. بارگذاری WASM غیرهمگام است ولی union همگام و در میانهٔ محاسبه قابل‌قطع نیست. تماس پایه، تعادل، چاپ، پخت و جدایش فیزیکی آزموده نشده‌اند.


### فرمت و مرزهای معماری
`npm run format` فرمت کد JS/TS/TSX، CSS، HTML و JSON شناخته‌شده را با Prettier اعمال می‌کند و `npm run format:check` بدون نوشتن کنترل می‌کند؛ هر دو کار lint و format:check در CI وب و کامپایل ویندوز اجرا می‌شوند. خروجی‌های تولیدی، وابستگی‌ها، lockfile و مستندات Markdown از قالب‌بندی کنار گذاشته شده‌اند. قواعد LF در Git از اختلاف خط‌پایان ویندوز جلوگیری می‌کنند.
ESLint برای بسته‌های داخلی لایه‌های زیر را کنترل می‌کند: config/schema/kernel/patterns مستقل از سایر بسته‌های داخلی؛ molds وابسته به kernel و exporters وابسته به kernel/config؛ storage فقط وابسته به config/schema. import محلی مجاز و import از apps برای تمام بسته‌ها ممنوع است. تست‌های `.test`/`.spec` برای آزمون یکپارچه می‌توانند به بسته‌های داخلی دیگر وابسته باشند. رابط apps مصرف‌کنندهٔ لایه‌هاست.
مسیرهای نسبی و alias با import/export و import پویا/require دارای رشتهٔ ثابت کنترل می‌شوند؛ این ابزار تحلیل computed import، resolver عمومی alias، بررسی وابستگی خارجی یا مرز امنیتی نیست. شش تست پیکربندی (۱۹ تست Node در مجموع) صحت lint، جهت وابستگی و رفتار فرمت را کنترل می‌کنند.


### اسلب‌تمپلیت توسعه‌پذیر
ابزار مستقل بخش خروجی سطح میانی استوانه یا مخروط ناقص را با شعاع بالا/پایین ۱۰–۱۵۰mm، ارتفاع ۱۰–۳۰۰mm و ۲–۲۴ بخش راهنما به صفحه توسعه می‌دهد. استوانه مستطیلی با عرض محیط و مخروط ناقص یک قطاع حلقوی با طول مولد `hypot(height, bottomRadius-topRadius)` است؛ جهت مخروط اندازهٔ قطاع را عوض نمی‌کند. اعوجاج نظری این سطوح صفر است، نه تضمین ساخت بدون تغییرشکل گل.
کانتور قطاع با خطای وتر حداکثر ۰٫۰۲mm و مختصات گرد‌شده تا شش رقم اعشار صادر می‌شود. فرمول پایدار نزدیک استوانه از حذف عددی در زاویه و ارتفاع جلوگیری می‌کند. راهنماها در پیش‌نمایش خط‌چین و در SVG/DXF خطوط ساده‌اند؛ پیش از برش باید از مرز اصلی جدا شوند. خروجی شامل ضخامت، لبهٔ اتصال، انقباض یا کف قطعه نیست و CAD/نمونه‌سازی واقعی هنوز لازم است.
۱۳ تست پارامتری و اعتبار ورودی، سه بازخوانی مستقل DXF و یک تست مرورگر (۶۴ تست کل) فایل‌های واقعی و استقلال تاریخچه را بررسی می‌کنند. پارامترها موقت‌اند و از فرم فعلی خوانده یا در پروژه/ZIP ذخیره نمی‌شوند. موارد ۷.۵ و ۸.۱۵ تا پیاده‌سازی فرم عمومی، محاسبه و آستانهٔ اعوجاج و خطوط تای مبتنی بر مش همچنان باز هستند.


### Loft / Sweep محدود
ابزار مستقل بخش خروجی دو حالت دارد: loft خطی بین دو بیضی با شعاع‌های X/Z بین ۵–۱۰۰mm، ارتفاع ۱۰–۳۰۰mm و جابه‌جایی X مقطع بالا بین ±۱۰۰mm؛ یا sweep مقطع دایره روی قوس صفحه‌ای با شعاع مسیر ۲۰–۱۵۰mm، شعاع مقطع ۲–۳۰mm و زاویهٔ ۱۵–۲۷۰ درجه. شعاع مقطع به نصف شعاع مسیر محدود است و کاهش شعاع مسیر مقدار نامجاز را محدود می‌کند.
Loft با تطابق زاویه‌ای ۹۶ رأس و دو درپوش بسته ساخته می‌شود؛ وجوه جانبی بین دو رینگ مثلثی‌اند. Sweep دارای ۶۴ رأس مقطع و ۹۶ گام مسیر با قاب کمینه‌چرخش قوس صفحه‌ای و بینرمال Z ثابت است؛ مسیر دلخواه سه‌بعدی یا الگوریتم عمومی parallel transport ندارد. حد شعاع و زاویه از تاشدگی محلی و بسته‌شدن مسیر جلوگیری می‌کند.
نمای رابط تصویر خطی X/Y رینگ‌هاست، عمق Z را نمایش نمی‌دهد و جایگزین بررسی CAD نیست. STL پس از اعتبارسنجی صادر می‌شود؛ تنظیمات مستقل و موقت‌اند، به فرم فعلی متصل نمی‌شوند و در پروژه/تاریخچه/ZIP نیستند. مسیر و پروفیل دلخواه، انقباض، تحمل بار و چاپ واقعی پشتیبانی/تأیید نشده‌اند.
۱۷ تست هندسی قطعیت، جهت/بستگی/حجم، loft جابه‌جا و sweep زاویه‌های مختلف و رد ورودی نامعتبر را کنترل می‌کنند؛ تست شصت‌وپنجم Chromium هر دو STL واقعی، مختصات، محدودسازی شعاع و استقلال تاریخچه را بررسی می‌کند.


### ردیابی محلی تصویر
در بخش خروجی، PNG/JPEG/WebP تا ۵ MiB پذیرفته می‌شود؛ پس از decode مرورگر، ابعاد بیش از ۴۰۹۶ پیکسل در هر جهت رد می‌شود. این بررسی سقف حافظهٔ decoder را تضمین نمی‌کند؛ از تصاویر بسیار بزرگ/نامطمئن استفاده نکنید. رستر کاری با حفظ نسبت (با گردکردن پیکسل) به حداکثر ۲۵۶ در هر بُعد کاهش می‌یابد. شفافیت روی سفید ترکیب و خاکستری با وزن‌های ۰٫۲۱۲۶/۰٫۷۱۵۲/۰٫۰۷۲۲ ساخته می‌شود.
Otsu با tie-break قطعی آستانهٔ کمتر، marching squares با مرز سفید و اتصال چهارتایی نواحی تیره و RDP تکراری اجرا می‌شوند. کانتورهای مماس با لبه بسته و مرز داخلی سوراخ‌ها هم صادر می‌شوند؛ تصویر یکنواخت خروجی ندارد. بیش از ۵۱۲ کانتور رد می‌شود. تلرانس RDP برابر ۰–۲mm است؛ کاهش یک حلقه به کمتر از سه نقطه با حفظ حلقهٔ اولیه جبران می‌شود. عدم تقاطع یا حفظ توپولوژی پس از ساده‌سازی تضمین نمی‌شود.
عرض مرجع ۱۰–۵۰۰mm عرض کل تصویر است (نه فاصلهٔ یک نشان داخل تصویر)؛ ارتفاع با نسبت رستر کاری محاسبه می‌شود. مختصات خروجی تا شش رقم اعشار گرد می‌شوند. SVG/DXF خطوط کانتور را صادر می‌کنند؛ تشخیص جزیره، پل، kerf و آزمون CAD/برش واقعی جداست. داده موقت و خارج از پروژه/تاریخچه/ZIP است و هیچ تصویر یا درخواستی برای پردازش به شبکه ارسال نمی‌شود. انتخاب جدید نتیجهٔ پیشین را کنار می‌گذارد؛ خطای decode دانلود قبلی را فعال نمی‌گذارد.
۱۲ تست هسته، دو بازخوانی مستقل DXF و تست شصت‌وششم Chromium با PNG واقعی، تغییر مقیاس، دو دانلود و فایل خراب اضافه شده است. خواندن فایل async است؛ هسته پس از decode همگام اجرا می‌شود و در میانهٔ محاسبه قابل‌قطع نیست.


### تشخیص جزیره در کانتورهای ردیابی
`detectIslands` چندضلعی‌های خطی با بسته‌شدن ضمنی را اعتبارسنجی می‌کند و برای هر کانتور، والد مستقیم، عمق، مساحت mm² و وضعیت جزیره برمی‌گرداند. ورودی حداکثر ۵۱۲ کانتور و ۴۰۹۶ رأس با مختصات محدود ±۱۰۰۰۰mm دارد. تقاطع، تماس بین کانتورها، خودتقاطع، رأس/لبهٔ تکراری و مساحت صفر رد می‌شوند؛ این تحلیل با رئوس گرد‌شدهٔ همان خروجی SVG/DXF انجام می‌شود، نه رستر اولیه.
با فرض بریده‌شدن نواحی تیره و قاعدهٔ زوج/فرد، عمق صفر مرز برش و عمق فرد جزیرهٔ مادهٔ باقی‌مانده است. جهت گردش و ترتیب ورودی اثر ندارد؛ آزمون نقطه در چندضلعی برای شکل مقعر نیز استفاده می‌شود. تماس/تقاطع یا سقف پیچیدگی پیام «تشخیص قطعی نیست» می‌دهد، نه نتیجهٔ صفر جزیره. تحلیل روی هندسهٔ ساده‌شده است و حفظ توپولوژی تصویر اصلی را تضمین نمی‌کند.
در ردیابی تصویر، جزیره‌ها با خط ضخیم نارنجی و شمار متنی مشخص می‌شوند؛ این علامت صرفاً تحلیلی است و فایل خروجی را تغییر نمی‌دهد. پل محدودِ کانتور خطی در بخش بعد توضیح داده شده؛ اتصال این تحلیل به همهٔ الگوهای منحنی، ویرایشگر مسیر دلخواه و تأیید ساخت باقی است. ۱۱ تست جهت/ترتیب، عمق سه، چندریشگی، شکل مقعر، تماس، تقاطع و ورودی نامعتبر و تست شصت‌وهفتم مرورگر با تصویر حلقهٔ واقعی افزوده شده است.


### پل نگهدارندهٔ جزیرهٔ ردیابی
پس از تشخیص معتبر جزیره، آن را انتخاب و عرض ۰٫۵–۱۰mm را تعیین کنید. «اعمال پل به کانتور برش» کوتاه‌ترین اتصال رأس/لبه بین کانتور جزیره و والد مستقیم را با tie-break قطعی پیدا می‌کند؛ نوار مستطیلی در دو سر به‌اندازهٔ نصف عرض امتداد دارد. عملیات `polygon-clipping` نوار را از چندضلعی‌های ناحیهٔ برش کم می‌کند تا مادهٔ پل باقی بماند؛ این کار یک خط نمایشی یا حذف سادهٔ چند رأس نیست. در اتصال به گوشه، امتداد مستطیل می‌تواند اندکی بیشتر از عرض×فاصله از ناحیهٔ برش کم کند.
کانتورهای خروجی تا شش رقم گرد و دوباره اعتبارسنجی می‌شوند؛ مساحت برش باید کمتر و شمار جزیره دقیقاً یکی کمتر شود، وگرنه هندسهٔ قبل با پیام خطا حفظ می‌شود. با انتخاب جزیرهٔ باقی‌مانده می‌توان پل بعدی با عرض متفاوت اعمال کرد. عرض جدید فقط روی اعمال بعدی اثر دارد؛ «حذف همهٔ پل‌ها» تصویر ردیابی اصلی را برمی‌گرداند. تغییر تصویر، عرض مرجع یا تلرانس نتایج پل را باطل می‌کند، نه اینکه پل قدیمی را بی‌صدا به مقیاس جدید منتقل کند.
پیش‌نمایش و SVG/DXF همان هندسهٔ پل‌خورده را مصرف می‌کنند؛ خروجی پل‌خورده فعلاً نام عمومی فایل ردیابی را دارد، پس هنگام نگه‌داشتن نسخه‌های مختلف نام فایل را مشخص کنید. نتیجه موقت و مستقل از پروژه/ZIP/تاریخچه است. مسیر دستی، ویرایش پل منفرد پس از اعمال، حداقل عرض مؤثر پس از kerf، حفظ همهٔ جزئیات نزدیک نوار، استحکام و برش واقعی تضمین نمی‌شوند؛ قبل از تولید در CAD و نمونهٔ واقعی بررسی شود.
هشت آزمون هسته عرض/مساحت، قطعیت، عدم تغییر ورودی، چند جزیره و اعمال پیاپی و ورودی نامعتبر را بررسی می‌کنند؛ یک بازخوانی مستقل DXF و تست شصت‌وهشتم مرورگر هندسهٔ واقعی، کاهش جزیره، بازنشانی و ابطال با تغییر مقیاس را پوشش می‌دهند.


### بررسی اختیاری نسخهٔ جدید
بخش «به‌روزرسانی — بررسی آنلاین اختیاری» فقط هنگام کلیک به API عمومی آخرین release مخزن `pranses2011/Sahand_Patturn` متصل می‌شود. در شروع، بازکردن بخش یا حین ویرایش بررسی خودکار وجود ندارد. درخواست بدون credentials، با cache غیرفعال و رد redirect اجرا می‌شود؛ timeout پانزده ثانیه و لغو صریح دارد. اطلاعات پروژه/پروفایل ارسال و نتیجه ذخیره نمی‌شود.
نسخهٔ پایدار با قالب `vMAJOR.MINOR.PATCH` یا بدون v و مؤلفه‌های صحیح امن مقایسه می‌شود؛ draft/prerelease و برچسب غیرمتعارف رد می‌شود. پاسخ حداکثر ۲۵۶KiB و ۱۰۰ دارایی دارد. نام ASCII محدودِ EXE/MSI و اندازهٔ ۱ بایت تا ۱GiB لازم است؛ URL دانلود از نام و tag روی نشانی ثابت همین مخزن ساخته می‌شود و URL دلخواه JSON نادیده گرفته می‌شود. پاسخ 404 به معنی نبود انتشار پایدار است، نه تأیید به‌روز یا آماده‌انتشار بودن برنامه.
لینک دریافت نصب‌کننده مرورگر را به GitHub هدایت می‌کند؛ دانلود/نصب/اجرای خودکار، تأیید checksum/امضا و ارتقای نصب‌شده در این قابلیت وجود ندارد. نسخهٔ جدید بدون دارایی معتبر فقط یادداشت انتشار را نشان می‌دهد. پیش از ارتقا پشتیبان بگیرید و ناشر و هش را جداگانه بررسی کنید؛ بازکردن لینک/نصب/ارتقای واقعی Tauri ویندوز هنوز تأیید نشده است. قطع سرویس، rate limit و پاسخ خراب مانع کار محلی نیستند و تلاش دوباره صریح است.
۹ آزمون نسخه/پاسخ/سقف/endpoint و دو تست مرورگر با API شبیه‌سازی‌شده، عدم درخواست خودکار، URL امن، خطای آفلاین، retry و حفظ ویرایش را بررسی می‌کنند (۷۰ تست مرورگر کل). این آزمون‌ها وجود نسخهٔ عمومی یا نصب‌کنندهٔ فعلی در سرویس را اثبات نمی‌کنند.


### مهرسازِ کانتور محدب
داخل ردیابی تصویر، پس از خواندن تصویر، بخش مهرساز کانتورهای فعلی را به برجستگی روی پایه تبدیل می‌کند. ورودی فعلی فقط شکل‌های محدب بدون سوراخ است؛ جعبه‌های محاطی شکل‌ها باید از هم جدا باشند، حتی اگر خود دو شکل نامحدب‌نیستند و تماس ندارند. این محدودیت محافظه‌کارانه ورود حروف سوراخ‌دار، طرح مقعر یا مهر عمومی را رد می‌کند؛ متن مستقیم و SVG دلخواه ورودی نیستند. حداکثر ۳۲ شکل، ۱۰۲۴ رأس و ابعاد کلی طرح ۲۰۰×۲۰۰mm پذیرفته می‌شود.
ضخامت پایه ۲–۱۰mm، برجستگی ۱–۸mm و حداقل عرض کالیپری شکل ۱–۵mm است. عرض کالیپری کمترین فاصلهٔ دو خط تکیه‌گاهی موازیِ هر چندضلعی محدب است؛ به معنی تضمین ضخامت نزدیک نوک تیز، شعاع گوشه یا عرض مؤثر پس از چاپ/kerf نیست. طرح تیره برجسته است؛ آینه‌سازی X پیش‌فرض روشن است تا اثر مهر به جهت اولیه برگردد.
پایه در XY با حاشیهٔ ۳mm ساخته می‌شود؛ برجستگی در +Z با هم‌پوشانی ۰٫۱mm به پایه union می‌شود و مش قبل از STL اعتبارسنجی می‌شود. مختصات خروجی برای چاپ با ابزارهای محور Y یکسان تفسیر نشود. تغییر کانتور، تنظیمات یا گزینهٔ آینه نتیجهٔ قبلی را باطل می‌کند؛ نتایج دیررس WASM پس از تغییر/unmount نادیده گرفته می‌شوند. داده مستقل و موقت و خارج از فایل پروژه/ZIP/تاریخچه است.
۹ تست CSG حجم، بستگی، آینه‌سازی نامتقارن، عدم تغییر ورودی و رد طرح باریک/مقعر/سوراخ‌دار را بررسی می‌کنند؛ تست هفتادویکم مرورگر PNG واقعی تا STL، ارتفاع واقعی، آینه و ابطال با تغییر مقیاس را می‌سنجد. دسته، شیب جدایش، انقباض، استحکام و کیفیت اثر مهر فیزیکی آزموده نشده‌اند.


### نمایش اعداد فارسی در ویرایشگر
`formatNumber` فقط لایهٔ ارائه را با `Intl.NumberFormat('fa-IR')` قالب‌بندی می‌کند: جداساز هزارگان، ارقام فارسی و دقت صریح ۰–۸ رقم؛ مقدار غایب/نامتناهی با «—» نمایش داده می‌شود. NumericControl مقدار تثبیت‌شده را فارسی نشان می‌دهد اما خود فیلد HTML number و draft همچنان عدد لاتین استاندارد مرورگر دارند؛ تلاش برای جایگزینی رشتهٔ فارسی در value انجام نمی‌شود. درصدِ نمایشی و توضیح دسترس‌پذیری آن «٪» است.
خلاصهٔ ابعاد و ظرفیت و نوار وضعیت، مصالح گچ/آب با kg و حجم با L، اعوجاج و برخی نتایج قالب اکنون فارسی‌اند. در خلاصهٔ ابعاد و نوار وضعیت و مقدار نمایشی کنترل‌ها `bdi` عدد و واحد را از متن RTL جدا می‌کند. گزارش متنی انسانی مصالح و مقدار نمایشی ظرفیت در PDF هم از قالب‌بند استفاده می‌کنند؛ دادهٔ هندسی، JSON پروژه، کلیدها و نام فایل‌ها عدد داخلی/ASCII خود را حفظ می‌کنند.
دو تست قالب‌بند و تست هفتادودوم Chromium فارسی‌بودن خلاصه و ثابت‌ماندن نوع number در پروژهٔ gzip و نام فایل ASCII را بررسی می‌کنند؛ تست‌های موجود پیش‌نویس اعشاری، undo و توضیح دسترس‌پذیر واحد نیز با متن جدید موفق‌اند. مورد ۱۰.۵ تا ممیزی تمام پیام‌ها و ابزارها و گزارش‌های جانبی همچنان باز است؛ این تغییر تأیید جامع WCAG یا نمایش تمام خروجی‌ها نیست.


### ادامهٔ ممیزی نمایش اعداد
شمار الگوهای پیدا‌شده/کل، شمار نسخه‌های بازیابی و پشتیبان پوشه، پیام تأیید/نتیجهٔ ادغام کتابخانه، شمارهٔ قطعات و نیمه‌ها و تعداد قطعات طرح تقسیم با قالب‌بند مشترک فارسی نمایش داده می‌شوند. اعداد انسانی گزارش BOM و راهنمای ZIP (جبران انقباض و شمار قطعات) نیز فارسی شدند؛ نام فایل‌های ارجاع‌شده، شناسه‌ها، شماره تماس/کارت و محتوای ماشینی JSON/OBJ/STL عمداً دست‌نخورده‌اند.
آزمون رندر کنترل عددی صریحاً وجود هم‌زمان نمایش `۱۲٫۵` و مقدار ورودی HTML برابر `12.5` و واحد دسترس‌پذیر `٪` را بررسی می‌کند. ۷۱۱ تست ماژولی، ۱۹ تست Node و هر ۷۲ تست مرورگر پس از اصلاح انتظارات متن فارسی موفق‌اند. مورد ۱۰.۵ هنوز بسته نیست: نوشته‌های عددی فنیِ PDF (خط‌کش/مبدأ/مقیاس) و پیام‌های برگشتی خطای زیرسامانه‌ها به ممیزی جداگانه نیاز دارند.


### عددهای فارسی در PDF ابعاد
قالب‌بند مشترک اکنون در `@patturn/config` قرار دارد و رابط و PDF همان پیاده‌سازی را مصرف می‌کنند. مسیر قدیمی رابط فقط بازصادرکننده است؛ exporters مجاز است علاوه بر kernel به config مستقل وابسته باشد. این تغییر به هستهٔ هندسی وابستگی نمایشی اضافه نمی‌کند.
جدول قطر/ارتفاع با سه رقم اعشار، تعداد صفحات، نسبت ۱:۱، برچسب‌های خط‌کش ۰ تا ۱۰۰، شمارهٔ ردیف/ستون و مختصات مبدأ صفحه در PDF با ارقام فارسی ساخته می‌شوند. واحدهای استاندارد mm و نام محورهای X/Y حفظ می‌شوند. مختصات خطوط، MediaBox، قطعه‌بندی صفحات، نام فایل و داده‌های ماشین هیچ قالب‌بندی محلی نمی‌گیرند. متن پارامتر دلخواهِ فرستاده‌شده توسط مصرف‌کننده به‌طور کورکورانه بازنویسی نمی‌شود.
آزمون تازه برچسب‌ها را برای پروفیل نه‌صفحه‌ای بدون تغییر مختصات عددی کنترل می‌کند؛ آزمون PDF واقعی همچنان خط‌کش ۱۰۰mm، صفحهٔ A4 و فونت تعبیه‌شده را بررسی می‌کند. ۷۱۲ تست ماژولی، ۱۹ تست Node و ۷۲ تست Chromium موفق‌اند. ظاهر نهایی در خوانشگر PDF واقعی و خوانشگر صفحه و رشته‌های خطای زیرسامانه‌ها هنوز ممیزی نشده‌اند؛ وضعیت باز ۱۰.۵ و WCAG تغییر نکرده است.


### آیکون جهت جریان رابط
`FlowArrow` فلش منطقیِ رو‌به‌جلو است و برای نتیجهٔ تحلیل قالب جای فلش متنی ثابت را می‌گیرد. مقدار CSS ارثی `--flow-direction` با نزدیک‌ترین جد دارای `dir="rtl"` برابر ‎−۱ و با `dir="ltr"` برابر ۱ می‌شود و `scaleX` روی پوشش HTML آیکون اعمال می‌شود؛ بدنه جهت را از سند می‌گیرد، نه یک RTL اجباری مستقل. در صورت نبود dir، پیش‌فرض LTR است؛ `dir="auto"` و جهت صرفاً CSS قرارداد این آیکون نیستند.
خود آیکون تزئینی `aria-hidden` است و SVG فوکوس نمی‌گیرد؛ معنای جمله در متن باقی می‌ماند. برای فلش محور X/Y/Z، نمای برش، شیب واقعی یا اندازه‌گذاری فنی از این مؤلفه استفاده نشود؛ آن‌ها با RTL نباید آینه شوند. یک تست رندر و تست هفتادوسوم Chromium تبدیل واقعی RTL→LTR→RTL را بدون تغییر تاریخچهٔ پروژه تأیید می‌کنند. این اصلاح به معنی تکمیل ممیزی WCAG یا آزمون خوانشگر صفحه نیست.


### دروازهٔ شواهد انتشار (هنوز عبور نکرده)
`npm run release:check` فقط هماهنگی متادیتای نسخه است؛ جای QA واقعی را نمی‌گیرد. فرمان جدید `npm run release:gate -- مسیر-گزارش.json` گزارش را به HEAD چهل‌رقمی، نسخه و SHA-256 متن کامل `11-QA-ACCEPTANCE.md` گره می‌زند و درخت کاری تغییرکرده را رد می‌کند. قالب اولیه را پس از تمیزشدن شاخه با `npm run --silent release:gate -- --template > .cache/release-evidence.json` بسازید؛ تمام موارد در قالب `pending` هستند، نه passed. هیچ قالب یا مدرک قبولی ساختگی در Git ذخیره نشده است.
همهٔ چک‌باکس‌های دستی و ردیف‌های جدول متریک بخش Release Gate الزام‌اند (اکنون ۵۸ مورد). شناسهٔ هر مورد از متن و عنوان بخش ساخته می‌شود؛ توضیح اولیهٔ note فقط یادآور نیاز مدرک است و باید با گزارش نتیجه جایگزین شود. هر check تنها id/status/note/evidence دارد؛ status فقط passed مجاز است، بدون N/A یا skip. تغییر QA یا نسخه یا commit مستلزم بازبینی و گزارش جدید است. reviewer باید نام بازبین و performedAt زمان قابل‌خواندن در ۳۰ روز اخیر و نه آینده باشد.
هر evidence یک path نسبی از ریشهٔ مخزن و sha256 دقیق فایل است؛ فایل باید موجود، معمولی و حداکثر ۵MiB باشد. مسیر مطلق، traversal، مسیر متنی .git و symlink بیرون مخزن رد می‌شوند. برای گزارش‌ها/شواهد موقت از مسیر نادیده‌گرفته‌شدهٔ `.cache` استفاده کنید تا خود شواهد درخت کاری را تغییر ندهند. اندازهٔ گزارش حداکثر ۱MiB است؛ فایل‌های ویدیو/نصب‌کننده را وارد Git نکنید، به‌جایش گزارش متنی آزمون با ارجاع به آن‌ها ارائه شود.
این ابزار فقط تمامیت و کامل‌بودن ساختار مدرک را کنترل می‌کند: نمی‌تواند راست‌بودن note، درستی نتیجهٔ متریک، هویت بازبین یا اجرای واقعی ویندوز/CAD/اسلایسر را اثبات کند و امضای رمزنگاری‌شدهٔ بازبین ندارد. گزارش مثبت باید دستی با اصل مدرک تطبیق داده شود. فرمان هیچ انتشار یا آپلودی انجام نمی‌دهد؛ هنوز به یک مسیر خودکار انتشار عمومی متصل نیست و انتشار دستی بیرون آن را مهار نمی‌کند. مورد ۱۲.۱۰ عمداً باز است و هیچ دروازهٔ واقعی انتشار عمومی عبور نکرده است.
پنج تست Node با دادهٔ آزمون مصنوعی، قبول ساختار کامل و رد مورد مفقود/pending/تکراری، هویت ناسازگار، تاریخ نامعتبر، تغییر فایل و فرار مسیر/symlink را می‌سنجند. این تست‌ها به `npm test` و CI کیفیت متصل‌اند؛ مجموع ۲۴ تست Node است. تست‌ها مدرک قبولی خودِ محصول نیستند.


### نسخهٔ مرورگر و مرز پلتفرم
همان SPA اصلی با `npm run dev` اجرا و با `npm run build` در `apps/web/dist` ساخته می‌شود. برای بررسی build از `npm run preview -w @patturn/web -- --host 0.0.0.0 --port 4173` استفاده کنید؛ preview سرور تولیدی نیست. برای میزبانی ثابت، محتوای کامل dist (شامل WASM/فونت/دارایی‌های chunk) را روی ریشهٔ یک میزبان HTTPS با MIME درست WASM قرار دهید؛ دادهٔ localStorage به origin میزبان وابسته است و تغییر دامنه آن را منتقل نمی‌کند. انتشار عمومی یا زیردایرکتوریِ base سفارشی در این نوبت آزموده/انجام نشده است.
مسیر مرورگری برای خروجی از دانلود مرورگر استفاده می‌کند و به API Tauri نیاز ندارد. خطای WebGL به‌تنهایی نباید ویرایش/خروجی را متوقف کند؛ آزمون‌های ۷۳گانهٔ Chromium مسیر فرم تا ZIP، تصویر تا کانتور، ابزارها، خطا و retry و رسم نرم‌افزاری را پوشش می‌دهند. این نسخه PWA یا Service Worker آفلاین ندارد؛ کار محلی پس از بارگذاری دارایی‌ها به معنی reload کامل بدون اینترنت نیست.
ESLint در تولید `kernel/patterns/schema/config`، import رشته‌ای Node builtins و Tauri/React/Three و دسترسی مستقیم به globals شناخته‌شدهٔ محیط (مانند window/document/localStorage/fetch/process) و globalThis متناظر را رد می‌کند. storage و apps آداپتور پلتفرم‌اند؛ تست‌ها برای آزمون یکپارچه استثنا دارند. دو تست تازه رد وابستگی محیطی و اجازهٔ الگوریتم خالص/آداپتور را بررسی می‌کنند؛ مجموع تست‌های Node اکنون ۲۶ است. این کنترل استاتیک محدود است، نه اثبات ایزوله‌بودن امنیتی یا تحلیل وابستگی متعدی/دسترسی محاسباتی دلخواه.

### اصلاح وضعیت پایگاه‌داده
SQLite در پوستهٔ Rust به‌عنوان plugin ثبت شده است، اما پروژه/تاریخچه هنوز از `localStorage` و پشتیبان فایل استفاده می‌کنند؛ schema، migration و مخزن Drizzle/SQLite به آن‌ها متصل نیست. ثبت plugin به معنی «SQLite منبع حقیقت پروژه است» نیست. تیک ۹.۴ باز شد و ۹.۱۲ با شواهد مرورگری بسته شد؛ شمار تکمیل‌شده‌ها همچنان ۸۹ از ۱۲۲ است. در این نوبت کد اجرایی Rust تغییر نکرد (فقط توضیح آن دقیق شد) و کامپایل یا اجرای تازهٔ ویندوز ادعا نمی‌شود.


### بارگذاری اختیاری ابزارهای خروجی
چاک، رینگ‌روندر، تقسیم افقی، پازل، اسلب، Loft/Sweep، ردیابی تصویر و فوت‌رینگ با wrapper مشترک `DeferredTool` فقط پس از اولین بازکردن بخش درخواست می‌شوند. رفتن به تب خروجی به‌تنهایی این هشت chunk را دریافت نمی‌کند. پس از بارگذاری، بستن بخش تنظیمات را حفظ می‌کند؛ ترک تب همچنان ابزار را unmount و تنظیمات موقت را بازنشانی می‌کند. کامپوننت بارگذاری‌شده props جدیدِ فرم را می‌گیرد و به snapshot زمان import محدود نیست.
خطای import در همان بخش نمایش داده می‌شود و پروژه و ابزارهای دیگر را متوقف نمی‌کند. دکمهٔ retry دوباره loader را فراخوانی می‌کند؛ بازیابی از خطای cache ماژول در همهٔ مرورگرها تضمین نیست و ممکن است پس از ذخیرهٔ پروژه نیاز به reload باشد. نتیجهٔ دیررس پس از unmount نادیده گرفته می‌شود. بارگذاری ابزار روی دستگاه متصل/میزبان وب به دریافت دارایی نیاز دارد؛ این تغییر ادعای PWA یا دانلود همهٔ chunkها برای reload آفلاین ندارد.
گزارش build قبل/بعد این تغییر: entry static از ۴۶۵۶۱۶ به ۴۳۱۲۱۰ بایت خام (gzip: ۱۵۰۰۹۲→۱۴۱۲۸۵)؛ گراف ادیتور شامل نمایشگر از ۹۷۱۲۶۲ به ۹۳۶۸۹۵ بایت خام (gzip: ۲۷۵۸۳۹→۲۶۷۰۴۹). این مقایسه روی build همین نوبت است، نه عدد قدیمی ۸۵۸KB پیش از افزوده‌شدن ابزارها. بودجهٔ محافظه‌کارانهٔ ۶۰۰۰۰۰ بایت خام هنوز برقرار نیست؛ هدف gzip در QA واحد متفاوتی دارد و با آن خلط نشود. LCP/TTI و حافظه/GPU اندازه‌گیری نشده‌اند.
`bundle:report` اکنون وجود هر هشت ورودی lazy و نبودشان در گراف اولیه را اجباری کنترل می‌کند، هرچند بودجهٔ کل همچنان غیرمسدودکننده است. سه تست wrapper و دو تست مرورگری درخواست شبکه، حفظ تنظیمات در collapse، props جدید، شکست import، retry loader مصنوعی و unmount را پوشش می‌دهند؛ مجموع ۷۱۶ تست ماژولی، ۲۶ تست Node و ۷۵ تست Chromium موفق است. وضعیت ۱۲.۹ باز می‌ماند.


### منحنی‌های درجه‌دو و نرم در DXF
علاوه بر C/c، مسیرهای Q/q، T/t و S/s در صادرکننده پشتیبانی می‌شوند. منحنی درجه‌دو با تبدیل دقیق کنترل‌ها به مکعبی تبدیل و سپس با همان الگوریتم De Casteljau محدود به تلرانس مدل تقریب می‌شود. S تنها پس از C/S کنترل پیشین را بازتاب می‌دهد و T تنها پس از Q/T؛ پس از move، خط، فرمان نامرتبط و close حالت کنترل بازنشانی می‌شود. مختصات نسبی و تکرار ضمنی پارامترها پشتیبانی می‌شوند.
هیچ منحنی Bézier بدون گزینهٔ صریح `bezierToleranceMm` پذیرفته نمی‌شود (بازهٔ ۰٫۰۰۱–۱mm؛ رابط موجود ۰٫۰۵mm). فرمان نامعتبر یا پارامتر ناقص، کل فایل را بدون بایت خروجی رد می‌کند؛ ZIP هم برای منحنی درجه‌دو بدون مجوز تقریب شکست می‌خورد. تقریب قبل از clipping انجام می‌شود و خط مرزی اضافی برای بستن مسیر باز ساخته نمی‌شود. خروجی بدون bounds از قرارداد POLYLINE موجود و خروجی boundsدار از LINE استفاده می‌کند.
۱۹ آزمون جدید شامل نمونه‌برداری فاصلهٔ منحنی درجه‌دو، هم‌ارزی کنترل‌های صریح/انعکاسی، حالت نسبی، پارامتر ضمنی، reset بین زیرمسیرها و نوع منحنی‌ها، clipping و رد ورودی ناقص/فاقد تلرانس‌اند؛ dxf-parser بایت‌های خروجی را مستقل می‌خواند. مجموع ۷۳۵ تست ماژولی و ۲۶ تست Node و ۷۵ تست Chromium موفق است. کمان بیضوی عمومی/مسیرهای دیگر SVG و آزمون CAD واقعی هنوز باقی‌اند؛ مورد ۵.۴ باز می‌ماند و این کار ورود SVG دلخواه به رابط را اضافه نمی‌کند.


### کمان بیضوی عمومی در DXF
صادرکننده A/a را در مسیرهای ترکیبی و تکرار ضمنی هفت پارامتر می‌خواند؛ rotation و large-arc/sweep (دقیقاً ۰ یا ۱) و مختصات نسبی پشتیبانی می‌شوند. radii منفی مطابق SVG قدرمطلق می‌شوند و شعاع کوچک برای رسیدن به دو انتها اصلاح می‌شود. شعاع صفر خط مستقیم است؛ انتهای یکسان کمان تازه ایجاد نمی‌کند. مسیر دقیق CIRCLE/ARC دایرویِ شناخته‌شدهٔ قبلی اولویت دارد و تغییر نکرده است.
کمان بیضوی عمومی به گزینهٔ صریحِ موجود `bezierToleranceMm` نیاز دارد (با وجود نام تاریخی، برای A نیز اعمال می‌شود). تبدیل endpoint→center طبق SVG و تقریب وتر با حد مشتق دوم `max(rx,ry) * stepAngle² / 8` انجام می‌شود؛ کران تحلیلی در حساب حقیقی است و خطای ممیزشناور جداست. هر کمان حداکثر ۱۶۳۸۴ سگمنت و شعاع تصحیح‌شده/مختصات میانی حداکثر قدرمطلق ۱e۷mm دارد؛ موارد نامعتبر/نامتناهی یا فراتر از سقف رد می‌شوند، نه اینکه کیفیت بی‌صدا کاهش یابد. این سقف به‌تنهایی بودجهٔ کل یک فایل با تعداد نامحدود مسیر نیست.
پس از تبدیل کمان، کنترل انعکاسی Bézier بازنشانی و clipping خطی روی همان تقریب اجرا می‌شود. ۱۶ آزمون تازه چرخش‌های مختلف، نمونه‌برداری فاصله، چهار ترکیب پرچم، اصلاح شعاع، حالت‌های صفر/هم‌انتها، ورودی ناقص، نسبی/ضمنی و هم‌ارزی مسیر و بازخوانی مستقل DXF را کنترل می‌کنند. کل ۷۵۱ تست ماژولی، ۲۶ تست Node و ۷۵ تست Chromium موفق‌اند.
پرچم فشرده و ادامهٔ پس از Z در اصلاح بعدی زیر پشتیبانی شده‌اند؛ این parser همچنان مفسر کامل سند XML/SVG و transformها نیست و مسیرهای فاقد هندسهٔ قابل‌ترسیم ممکن است صریحاً رد شوند. این قابلیت ورود SVG دلخواه به رابط را اضافه نمی‌کند. مشاهده در CAD واقعی/اسلایسر و تأیید برش باقی است؛ ۵.۴ عمداً باز مانده است.


### بستن شکاف‌های grammar و بودجهٔ کل DXF
پرچم large/sweep کمان اکنون تک‌رقمی خوانده می‌شود؛ بنابراین رشته‌هایی مانند `A20 10 30 0140 0` یا پرچم چسبیده به مختصات اعشاری/علامت‌دار با نسخهٔ جداشده هم‌ارزند. پرچم خارج از ۰/۱ همچنان خطاست. فرمان پس از Z از نقطهٔ شروع زیرمسیر بسته ادامه می‌یابد و به‌صورت زیرمسیر تازه باز صادر می‌شود؛ بستن مکرر Z هم خروجی اضافه ایجاد نمی‌کند. کنترل‌های انعکاسی پس از Z و A بازنشانی می‌شوند.
بودجهٔ مشترک فایل، نه فقط یک منحنی: حداکثر ۴۰۹۶ مسیر، مجموع ۱۰۴۸۵۷۶ نویسهٔ UTF-16 در همهٔ path dataها و ۱۰۰۰۰۰ رأس تولیدشده در مسیرهای خطی/تقریب‌شده. رأس شروع زیرمسیر و شروع ادامهٔ پس از Z هم در بودجه شمرده می‌شوند. دایره/کمان دقیق با سقف شمار مسیر محدود می‌شود. این سقف محدودیت دقیق بایت فایل خروجی یا peak memory نیست. ورودی بیش‌ازحد، قبل از تحویل فایل با `DXF_PATH_LIMIT`، `DXF_PATH_CHARACTER_LIMIT` یا `DXF_VERTEX_LIMIT` رد می‌شود؛ بایت نیمه‌کاره تحویل داده نمی‌شود.
۱۴ تست تازه هم‌ارزی grammar و flags، close/open واقعی در parser مستقل، رد پرچم/حالت شروع نامعتبر و عبور از سقف در مجموعه‌ای از مسیرهای کوچک را می‌سنجند. مجموع ۷۶۵ تست ماژولی، ۲۶ تست Node و ۷۵ تست مرورگر موفق است. مشاهدهٔ واقعی CAD و ورود/تفسیر سند کامل SVG هنوز باقی است و تیک ۵.۴ تغییر نکرده است.


### اعتبارسنجی جداکننده‌های مسیر DXF
پیش از تشخیص دایره/قوس دقیق یا تقریب منحنی، ویرگول ابتدا/انتهای مسیر، ویرگول تکراری (حتی با فاصلهٔ میانی) و ویرگول کنار فرمان با `DXF_INVALID_SEPARATOR` رد می‌شود. فاصلهٔ مجاز SVG فقط space، tab، CR و LF است؛ NBSP، vertical tab، form feed و جداکنندهٔ سطر Unicode با `DXF_INVALID_PATH` رد می‌شوند. خطا در هر مسیر، کل خروجی را بدون بایت نیمه‌کاره رد می‌کند. ویرگول معتبر بین آرگومان‌ها، نمای علمی، اعشار چسبیده و پرچم فشردهٔ کمان همچنان پشتیبانی می‌شوند. این اصلاح ادعای پیاده‌سازی تمام grammar یا ورود سند SVG نیست.
۲۰ تست تازه شامل ۱۵ ورودی نامعتبر و ۵ هم‌ارزی معتبر است؛ مجموع ۷۸۵ تست ماژولی، ۲۶ تست Node و ۷۵ تست مرورگر موفق‌اند. آزمون واقعی CAD همچنان انجام نشده و مورد ۵.۴ باز است.


### راهنمای فارسی خطای DXF
۲۶ کد شناخته‌شدهٔ خطای DXF در لایهٔ نمایش به پیام فارسی علت/اقدام تبدیل می‌شوند: سقف پیچیدگی/تعداد/طول، دقت تقریب، تنظیمات و مختصات، بوم، مسیر خالی، پرچم، جداکننده و ترتیب فرمان. خروجی مستقیم الگو، خطای بستهٔ ZIP و خروجی DXF ابزارهای اسلب، پازل و ردیابی تصویر از نگاشت مشترک استفاده می‌کنند. خطای ناشناخته عمداً عیناً حفظ می‌شود تا اشکال برنامه‌نویسی پنهان نشود؛ این نگاشت جای اعتبارسنجی یا بهبود هندسه نیست. اعداد محدودیت ZIP نیز با قالب‌بند فارسی نمایش داده می‌شوند؛ نام فایل، کد خطای صادرکننده و اعداد ماشینی تغییر نکرده‌اند.
۲۷ تست تازه مسیر رشته، Error و پیشوند Error همراه جزئیات، نگاشت مشترک ZIP و حفظ خطای ناشناخته را می‌سنجند؛ مجموع ۸۱۲ تست ماژولی، ۲۶ تست Node و ۷۵ تست Chromium موفق است. پوشش تمام پیام‌های دیگر زیرسامانه‌ها یا آزمون واقعی خوانشگر/PDF هنوز ادعا نمی‌شود و مورد ۱۰.۵ باز است.


### ریب‌ساز دوبعدی از پروفیل داخلی
در بخش خروجی، «ریب‌ساز — الگوی دوبعدی پروفیل داخلی» لبهٔ تماس را از نمونه‌های پروفیل داخلی فعلی (با لحاظ دیوارهٔ شعاعی) می‌گیرد. بدنه سمت محور و پشت آن خط مستقیم است؛ عرض افقی پشت ۵ تا ۸۰mm است، نه فاصلهٔ عمود یا آفست ثابت منحنی. نقاط ارتفاع باید اکیداً صعودی و تعدادشان ۲ تا ۵۱۲ باشد؛ شعاع ۰ تا ۱۰۰۰mm، قدرمطلق ارتفاع حداکثر ۱۰۰۰۰mm و ابعاد نهایی هرکدام ۱ تا ۱۰۰۰mm محدودند. مسیر بسته با دقت نوشتاری شش رقم اعشار صادر می‌شود؛ این دقت، تضمین فاصله از منحنی تحلیلی یا دقت ساخت نیست.
پیش‌نمایش و خروجی SVG/DXF میلی‌متری با تغییر عرض پشت یا ورودی پروفیل به‌روز می‌شوند. تنظیمات موقت‌اند و وارد history، فایل پروژه یا ZIP نمی‌شوند؛ بستن و بازکردن همان پنل مقدار عرض را نگه می‌دارد. ابزار نهم فقط با بازشدن بارگذاری می‌شود و گزارش bundle نبودنش در گراف اولیه را بررسی می‌کند. در این ساخت مجموع گراف ادیتور/نمایشگر ۹۴۲۷۵۹ بایت خام است؛ بودجهٔ ۶۰۰۰۰۰ هنوز محقق نشده است.
۲۰ تست هندسه (لبهٔ تماس، ابعاد، قطعیت، عدم تغییر ورودی، انتقال مبدأ و ورودی نامعتبر)، سه تست SVG و بازخوانی مستقل DXF و یک سناریوی مرورگر برای تغییر عرض، فایل‌های خروجی، حفظ تنظیمات و عدم ایجاد history موفق‌اند. مجموع ۸۳۵ تست ماژولی، ۲۶ تست Node و ۷۶ تست مرورگر موفق است. ریب سه‌بعدی/ضخامت، STL/PDF، انقباض/لقی و آزمون ساخت واقعی هنوز پیاده‌سازی یا تأیید نشده‌اند؛ مورد ۸.۶ باز است.


### ریب سه‌بعدی و STL اعتبارسنجی‌شده
در ادامهٔ ریب دوبعدی، کنترل ضخامت ۱ تا ۱۲mm و نمای جانبی ضخامت افزوده شد. اکستروژن در Z با ضخامت یکنواخت از همان نقاط لبهٔ تماس دوبعدی ساخته می‌شود؛ پشت در X=0 و لبهٔ تماس در سمت +X است. محورها مختصات محلی ابزار هستند، نه محل مونتاژ روی فرم. STL از مختصات عددی و Float32 استفاده می‌کند؛ SVG/DXF با شش رقم اعشار نوشته می‌شوند و ممکن است در حد گردکردن تفاوت داشته باشند. نوک تیز/پخ، سوراخ گرفتن، انقباض و لقی افزوده نشده‌اند.
مش نواری برای تمام سطوح از رئوس مشترک استفاده می‌کند تا پشت مستقیم هم T-junction نداشته باشد. ورودی سه‌بعدی ۲ تا ۵۱۲ نقطه، X بین ۵ و ۱۰۰۰mm، Y بین ۰ و ۱۰۰۰mm و فاصلهٔ ارتفاع دست‌کم ۰٫۰۰۱mm می‌خواهد؛ در نتیجه هر نواری ارتفاع و عرض مثبت دارد. پیش از دانلود، `toBinaryStl` اعتبارسنجی معمول مش را اجرا می‌کند؛ شکست به پیام فارسی و عدم تحویل فایل منجر می‌شود. این اعتبارسنجی و هندسهٔ محدود تک‌مؤلفه‌ای جای آزمون اسلایسر و استحکام فیزیکی را نمی‌گیرد.
۲۸ تست تازهٔ kernel شامل ضخامت‌های حداقل/میانی/حداکثر، پروفیل مستقیم/غیرمحدب/۵۱۲نقطه‌ای، حجم حاصل از مجموع ذوزنقه‌ها، Euler=2، لبهٔ باز صفر، جهت مخالف لبه‌های مشترک، قطعیت/عدم تغییر ورودی و رد دادهٔ نامعتبر است. یک تست صادرکننده طول بایت و هدر mm فایل STL را می‌سنجد؛ مرورگر تازه نیز ضخامت شش میلی‌متر در بایت‌های STL، نمای ضخامت، عدم تغییر تاریخچه و به‌روزرسانی پروفیل با تغییر دیواره را بررسی می‌کند. مجموع ۸۶۴ تست ماژولی، ۲۶ تست Node و ۷۷ تست مرورگر موفق است. مواردِ باقی‌ماندهٔ پاراگراف قبلی دربارهٔ STL/ضخامت با این اصلاح رفع شده‌اند؛ PDF ریب و تأیید ساخت واقعی همچنان باقی‌اند و ۸.۶ باز است. اندازهٔ خام گراف اولیهٔ ادیتور/نمایشگر همان ۹۴۲۷۵۹ بایت مانده است و این ابزار فقط با بازشدن بارگیری می‌شود.


### PDF ریب با مقیاس واقعی و لغو امن
اصلاح بعدی، PDF ریبِ باقی‌مانده از بخش قبل را اضافه می‌کند: دکمهٔ «دانلود PDF ریب» با فونت فارسی محلی، برگهٔ آ۴، مختصات میلی‌متری ۱:۱ و خط‌کش واقعی ۱۰۰mm. طرح‌های بزرگ در کاشی‌های ۱۸۰×۲۳۰mm بدون کوچک‌سازی صفحه‌بندی می‌شوند (با سقف ابعاد ورودی، حداکثر ۳۶ صفحه). کادرها لب‌به‌لب کنار هم قرار می‌گیرند؛ کادر و شبکهٔ ده‌میلی‌متری خط برش نیستند. جهت هندسه همان SVG است؛ PDF تنها یک لبهٔ ریب را رسم می‌کند، نه قرینهٔ آن. ضخامت به‌صورت برچسب فارسی درج می‌شود و فایل نقشهٔ دوبعدی است، نه حجم سه‌بعدی.
هندسه پیش از import فونت/موتور PDF snapshot و با همان قیود مش ریب اعتبارسنجی می‌شود. خروجی در حال ساخت قابل لغو است؛ تغییر عرض/ضخامت/پروفیل یا خروج از پنل، درخواست قدیمی را abort و نتیجهٔ دیررسش را کنار می‌گذارد. لغو، دانلود ناقص تولید نمی‌کند و تلاش دوباره ممکن است. لغو، بارگیری شبکه‌ایِ import مشترک را متوقف نمی‌کند و بین صفحات فرصت تحویل رویداد می‌دهد، نه حین نوشتن یک صفحه. تاریخ و شناسهٔ سند ثابت‌اند تا ورودی یکسان بایت یکسان بدهد.
۱۱ تست تازه، آ۴ و فونت جاسازی‌شده، طول دقیق خط‌کش، مختصات تماس بدون قرینه/تغییر مقیاس، مرز کاشی‌ها/شمار صفحه، قطعیت، snapshot، لغو قبل/حین ساخت و ورودی نامعتبر را پوشش می‌دهند. دو تست مرورگر، فونت با بارگیری نگه‌داشته‌شده، لغو/تلاش دوباره و تغییر تنظیمات در زمان انتظار بدون تحویل فایل قدیمی را می‌سنجند. مجموع ۸۷۵ تست ماژولی، ۲۶ تست Node و ۷۹ تست Chromium موفق است. تست چاپگر، نمایش واقعی متن PDF و ساخت/کاربرد فیزیکی هنوز انجام نشده؛ مورد ۸.۶ تا تأیید عملی باز می‌ماند. گزارش بسته PDF/فونت را خارج از گراف اولیه کنترل می‌کند؛ گراف فعلی ادیتور/نمایشگر ۹۴۵۹۰۵ بایت خام است و بودجهٔ ۶۰۰۰۰۰ هنوز محقق نشده است.


### زیرساخت تاریخچهٔ SQLite/Drizzle (هنوز متصل به رابط نیست)
بستهٔ storage اکنون `SqliteEditorHistory` و کارخانهٔ تعویقی `desktopSqliteHistory` دارد. جدول `patturn_editor_history` در `sqlite:patturn.db` یک سند تاریخچهٔ پارامترها را با شمارهٔ قالب و revision نگه می‌دارد؛ schema نسخهٔ یک با CREATE IF NOT EXISTS راه‌اندازی می‌شود. این مهاجرت idempotent اولیه است، نه سامانهٔ کامل ارتقای نسخه‌های بعدی. تاریخچه همان اعتبارسنجی EditorState/شناسهٔ الگو، نگهداری ده نسخه، حذف ذخیرهٔ بی‌تغییر و restore مخزن مرورگری را به‌کار می‌گیرد؛ مش ذخیره نمی‌شود. فهرست، ذخیره و بازیابی ناهمگام‌اند.
ذخیره با INSERT شرطی یا UPDATE شرط‌دار روی revision و version و RETURNING انجام می‌شود؛ از BEGIN/COMMIT چنددستوری روی اتصال‌های تجمیع‌شده استفاده نشده است. رقابت نویسندگان با `SQLITE_HISTORY_CONFLICT` شکست آشکار می‌خورد و دادهٔ جدیدتر بی‌صدا حذف نمی‌شود. سند خراب، نسخهٔ ناشناخته و پایان بازهٔ revision بازنویسی نمی‌شوند. خطاهای خواندن/نوشتن با کد ثابت و cause داخلی منتقل می‌شوند تا پیام خطای بیرونی حاوی پارامترهای SQL و کل JSON پروژه نباشد. snapshot پارامترها و زمان پیش از نخستین await گرفته می‌شود. همهٔ مقادیر SQL bind می‌شوند؛ ترتیب کلیدهای شیء خروجی درایور به ترتیب ستون‌ها وابسته نیست.
۱۳ تست روی `node:sqlite` واقعی شامل حافظه و فایل موقت، بسته‌شدن/بازگشایی اتصال، حفظ دادهٔ خراب، نسخهٔ آینده، خطای نوشتن و تلاش دوباره، رقابت درج اولیه و به‌روزرسانی، حفظ snapshot، اعتبارسنجی، retry راه‌اندازی، ترتیب ستون‌ها، پاک‌سازی پیام خطا و سقف revision موفق‌اند. تست‌های Node 22 ممکن است اخطار experimental SQLite بدهند. فایل دیتابیس تست در پوشهٔ موقت ساخته و حذف می‌شود و وارد Git نمی‌شود. مجموع ۸۸۸ تست ماژولی، ۲۶ تست Node و ۷۹ تست مرورگر موفق است؛ ساخت و گزارش بسته نیز موفق‌اند و گراف اولیه همان ۹۴۵۹۰۵ بایت خام است.
**وضعیت واقعی:** رابط ادیتور همچنان startup/autosave/restore را با localStorage انجام می‌دهد. کارخانهٔ جدید هیچ fallback پنهانی از SQL ناموفق به localStorage ندارد، اما هنوز از رابط فراخوانی نمی‌شود. انتقال غیرمخرب دادهٔ قدیمی، اتصال رابط و مخزن عمومی پروژه‌ها، مهاجرت‌های بعدی و آزمون عملی Tauri/ویندوز باقی‌اند. بنابراین ۹.۴ همچنان باز است و SQLite هنوز منبع حقیقت رابط نیست.


### اتصال واقعی تاریخچهٔ ادیتور دسکتاپ به SQLite
در اصلاح بعدی، محدودیت اتصال رابطِ بخش قبل رفع شد: `EditorBoot` در محیط Tauri ابتدا SQLite را باز می‌کند، تاریخچه را اعتبارسنجی/در صورت نیاز منتقل می‌کند، سپس ادیتور را با همان مخزن ناهمگام راه‌اندازی می‌کند. startup، autosave و restore تاریخچهٔ دسکتاپ از SQLite استفاده می‌کنند. مسیر مرورگری بدون انتظار برای SQL همان localStorage است؛ کتابخانهٔ الگو و پروفایل محلی دسکتاپ نیز همچنان localStorage هستند، نه SQL. این تغییر هنوز مخزن عمومی چندپروژه‌ای نیست.
انتقال فقط وقتی ردیف SQL وجود ندارد انجام می‌شود؛ تمام حداکثر ده ورودی معتبر با شناسه/زمان قبلی و قالب `patturn:last` حفظ می‌شوند. هیچ کلیدی حذف یا بازنویسی نمی‌شود. وجود SQL معتبر بر منبع قدیمی مقدم است و حتی getter مسدود localStorage هم خوانده نمی‌شود. منبع قدیمی خراب یا غیرقابل‌خواندن روی دیتابیس خالی، startup را با پیام و دکمهٔ تلاش دوباره متوقف می‌کند؛ در این حالت ویرایشگر هنوز باز نیست، پس فایل خروجی هم از آن قابل ساخت نیست. SQL خراب، مهاجرت و ذخیره را متوقف می‌کند و به localStorage fallback نمی‌کند. رقابت درج مهاجرت با ذخیره، برندهٔ SQL را حفظ می‌کند.
ذخیره‌ها سریالی‌اند؛ موفقیت یک snapshot قدیمی، پارامترهای تازه‌تر را «ذخیره شد» اعلام نمی‌کند و snapshot تازه پس از تأخیر بعدی ذخیره می‌شود. پس از شکست، همان snapshot خودکار در حلقه تکرار نمی‌شود؛ تلاش دوبارهٔ کاربر یا ویرایش تازه لازم است. بازیابی ناهمگام هم اگر هنگام انتظار پارامترها تغییر کنند، درخواست دوباره می‌خواهد. نتیجهٔ دیررس پس از unmount نادیده گرفته می‌شود، ولی نوشتن SQL آغازشده واقعاً لغو نمی‌شود. بکاپ پوشه‌ای فقط پس از موفقیت SQL برای همان snapshot درخواست می‌شود.
پنج تست تازهٔ انتقال روی SQLite واقعی و چهار تست boot (انتظار قبل از mount، شکست/تلاش دوباره، مسیر مرورگر و نتیجهٔ دیررس) افزوده شد. چهار تست Chromium با **IPC شبیه‌سازی‌شدهٔ Tauri و SQLite واقعی در فرایند تست**، انتقال/ذخیره/reload/restore، startup ناموفق و دادهٔ خراب، نوشتن دیررس و شکست نوشتن/تلاش دوباره بدون fallback را پوشش می‌دهند؛ این شواهد اجرای نصب‌شدهٔ ویندوز نیستند. مجموع ۸۹۷ تست ماژولی، ۲۶ تست Node و ۸۳ تست مرورگر موفق‌اند. گزارش بسته نبودن مخزن Drizzle/SQLite در گراف اولیه را هم کنترل می‌کند؛ گراف ادیتور/نمایشگر ۹۴۸۴۲۰ بایت خام است و بودجه هنوز محقق نشده. مورد ۹.۴ برای مخزن عمومی پروژه‌ها، مهاجرت‌های بعدی و تأیید واقعی ویندوز باز می‌ماند.


### دای اکسترودر آزمایشی با قطر دستی
در بخش خروجی، «دای اکسترودر — سوراخ گرد و قطر دستی» اضافه شد: قطر بیرونی ۳۰–۱۵۰mm، ضخامت ۳–۲۰mm، قطر سوراخ ۲–۴۰mm و تعداد ۱–۱۲. یک سوراخ در مرکز است؛ چند سوراخ روی یک دایره با شعاع ۰–۶۰mm قرار می‌گیرند (شعاع نامناسب رد می‌شود). مرز بیرونی ۱۲۸ضلعی و سوراخ‌ها ۶۴ضلعی‌اند؛ این‌ها قطر اسمیِ دایرهٔ محیطی‌اند، نه دایرهٔ تحلیلی یا جبران fit دستگاه.
فاصلهٔ امن از کمینهٔ «شعاع دایرهٔ محاطی مرز بیرونی منهای فاصلهٔ مرکز سوراخ و شعاع محیطی سوراخ» و «فاصلهٔ مراکز مجاور منهای قطر سوراخ» محاسبه و ۰٫۰۰۱mm برای گردکردن کسر می‌شود. مقدار کمتر از ۱٫۵mm پیش از extrusion رد می‌شود؛ فاصلهٔ چندضلعی واقعی از این bound کمتر نیست، جز خطای محاسبات عددی که حاشیه برایش در نظر گرفته شده است. این فاصلهٔ هندسی **تضمین استحکام، تحمل فشار، ایمنی چاپ سه‌بعدی یا سازگاری با دستگاه نیست**. پیش از کاربرد واقعی، مواد، قطر، اتصال و بار باید جداگانه بررسی شوند؛ استفادهٔ تحت فشار صرفاً بر اساس این مدل توصیه نمی‌شود.
SVG/DXF مرزهای بستهٔ همسان با مدل را با مرکز مسیر برش و بدون kerf می‌دهند. STL با CrossSection/EvenOdd و extrusion یکنواخت ساخته و برای بسته‌بودن، حجم مثبت و Euler/genus متناسب با تعداد سوراخ‌ها کنترل می‌شود؛ صادرکنندهٔ STL نیز اعتبارسنجی معمول را پیش از تحویل اجرا می‌کند. خطای WASM، فایل نامعتبر تحویل نمی‌دهد و SVG/DXF همچنان قابل‌ساخت‌اند؛ تلاش دوبارهٔ بارگذاری محلی ممکن است. نتیجهٔ منتظر بارگیری پس از تغییر تنظیمات/unmount کنار گذاشته می‌شود؛ ساخت محدود CSG پس از بارگیری فعلاً همگام روی رشتهٔ اصلی است، نه worker یا عملیات قابل‌لغو حین محاسبه.
ابزار دهم فقط پس از بازشدن بارگیری می‌شود، با بستن پنل تنظیماتش باقی می‌ماند و خارج از پروژه/history/ZIP است. ۲۴ تست layout برای bound همهٔ جفت‌ها و لبه و ورودی نامعتبر، شش تست مش با حجم چندضلعی تحلیلی و سوراخ‌های واقعی، سه تست خروجی با بازخوانی مستقل DXF و دو مرورگر فایل‌ها/ضخامت/منع web نازک/حفظ تنظیمات/شکست WASM و retry موفق‌اند. مجموع ۹۳۰ تست ماژولی، ۲۶ تست Node و ۸۵ تست Chromium موفق است. گراف اولیهٔ ادیتور/نمایشگر ۹۴۹۸۳۳ بایت خام است و بودجهٔ ۶۰۰۰۰۰ هنوز محقق نشده است. قطرهای برندها، فلنج و نوع اتصال، الگوی برش آزاد و آزمون مکانیکی هنوز باقی‌اند؛ ۸.۱۰ باز است. جبران انقباض اعمال نمی‌شود، چون دای ابزار است نه قطعهٔ رسی.
