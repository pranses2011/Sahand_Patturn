## 🔴 قوانین گردش نسخه (Version Control)

### R-001 — به‌روزرسانی قبل از هر تغییر 🔴 حذف‌نشدنی

> **قبل از هر تغییری** هوش مصنوعی باید از به‌روز بودن آخرین نسخه اطمینان حاصل کند.

```
قبل از شروع هر نوبت کاری یا هر تغییر:
  1. git status                  ← ببین چه چیزی dirty است
  2. git pull --ff-only           ← آخرین نسخهٔ شاخه را بگیر (بدون merge غیرضروری)
  3. اگر pull شکست خورد → ابتدا conflict را حل کن، بعد تغییر بده
  4. اگر pull ممکن نبود → به کاربر اطلاع بده و ادامه نده
```

**چرا:** جلوگیری از کار روی کد کهنه، conflictهای بزرگ و از دست رفتن تغییرات دیگران.

---

### R-002 — کامیت و پوش فارسی بعد از هر تغییر 🔴 حذف‌نشدنی

> بعد از **هر تغییر معنادار**، هوش مصنوعی باید کامیت و پوش را همراه با **توضیحات فارسی** انجام دهد.

```
بعد از هر تغییر (یک واحد منطقی کامل):
  1. git add <فایل‌های مرتبط>     ← فقط فایل‌های همان تغییر
  2. git commit -m "<پیام فارسی استاندارد>"   ← R-003
  3. git push origin <شاخهٔ فعال>  ← همیشه همان شاخهٔ جاری session
```

**چرا:** هیچ تغییری نباید بدون هویت و توضیح فارسی در تاریخچه بماند؛ پوش تضمین میکند کار کاربر از دست نرود.

**استثنا:** تغییرات ناتمام/خراب موقتی را کامیت نکن؛ یا کار را کامل کن یا نگه دار.

---

### R-003 — پیام کامیت استاندارد فارسی 🔴

قالب اجباری پیام کامیت:

```
<فعل فارسی + شرح کوتاه تغییر>

- <تغییر ۱ با جزئیات کوتاه>
- <تغییر ۲>
- <تغییر ۳ در صورت چندبخشی بودن>
```

**نمونه‌های معتبر:**
```
افزودن فایل قوانین و چک‌لیست وظایف

- 15-RULES.md با ۱۷ قانون لازم‌الاجرا و قالب افزودن قانون
- 14-CHECKLIST.md با ۱۳۲ کار تیک‌خوردنی در ۱۳ بخش
- اعمال R-001 و R-002 روی همین تغییر
```

**ممنوع:** پیام‌هایی مثل `fix`, `update`, `wip`, `misc` بدون شرح فارسی.

---

### R-004 — کار فقط روی شاخهٔ فعال 🔴

- شاخهٔ جاری session را تغییر نده، شاخهٔ جدید نساز (مگر کاربر صریحاً بخواهد).
- push فقط به شاخهٔ فعال: `git push origin <branch>` — هرگز به `main` یا شاخهٔ دیگر مستقیم پوش نکن.
- merge/pull request فقط با اجازهٔ کاربر.

---

### R-005 — بدون کامیت فایل‌های حساس 🔴

- `.env`، کلیدها، توکن‌ها، رمزها، اطلاعات شخصی کاربر هرگز کامیت نشوند.
- خروجی‌های build، نصب‌کننده‌ها و دیتاست‌های بزرگ در Git نروند (مسیرهای `.gitignore`).
- اگر سهواً فایل حساس کامیت شد → فوری: حذف از تاریخچه + اطلاع به کاربر.

## 🧮 قوانین هندسی و محصول

### R-006 — واحد میلی‌متر 🔴 حذف‌نشدنی

همهٔ محاسبات داخلی با `number` در میلی‌متر. تبدیل اینچ/سانتی‌متر فقط در لایهٔ نمایش. هیچ فایل خروجی بدون واحد صریح mm تولید نشود.

### R-007 — پروژه = پارامتر، نه مش 🔴 حذف‌نشدنی

فایل پروژه فقط JSON پارامترهاست (`schemaVersion` دارد). مش همیشه از پارامتر بازتولید میشود. ذخیرهٔ مش به‌عنوان منبع حقیقت ممنوع است.

### R-008 — قطعیت هندسی 🔴 حذف‌نشدنی

همان پارامترها → همیشه همان مش (هش یکسان). `Math.random()` بدون seed ممنوع. نتایج تست‌های طلایی قابل تغییر با «به‌بودی» نیستند؛ فقط با اصلاح باگ.

### R-009 — واترتایت بودن خروجی 🔴 حذف‌نشدنی

قبل از هر export STL: بررسی لبهٔ باز، نرمال، خودتقاطع، Euler. اگر نقص بود → ترمیم خودکار یا پیام فارسی به کاربر؛ خروجی خراب هرگز تحویل داده نشود.

## ✅ قوانین کیفیت

### R-010 — تست قبل از «تمام شد» 🔴

هیچ کاری «انجام شد» اعلام نشود مگر:
1. تست‌های مرتبط نوشته و سبز شده باشند،
2. اعداد مرجع (1131ml، 958ml، 1.72/1.20kg، …) رعایت شده باشند،
3. وضعیت در `14-CHECKLIST.md` تیک خورده باشد.

### R-015 — به‌روزرسانی چک‌لیست 🟠

بعد از اتمام هر کار از `14-CHECKLIST.md`: ردیف مربوطه `[x]` شود و شمارندهٔ «خلاصهٔ پیشرفت» به‌روز گردد.

### R-017 — عدم تغییر بی‌دلیل اسناد 🟠

فایل‌های این بسته فقط وقتی تغییر میکنند که:
- کاربر خواسته باشد، یا
- قانون/الزام جدیدی اضافه شده باشد، یا
- اصلاح واقعی (عدد اشتباه، لینک خراب) لازم باشد.
بازنویسی تزئینی و بدون دلیل ممنوع است.

- نسخهٔ اصلی محصول: **نصب‌شدنی روی ویندوز، اجرای کاملاً آفلاین**.

## ➕ قالب افزودن قانون جدید

هر قانون جدید با این قالب به فهرست بالا اضافه شود:

```markdown
### R-XXX — <عنوان کوتاه فارسی> <🔴 حذف‌نشدنی | 🟠 فعال | 🟡 آزمایشی>

> <یک جملهٔ اصل قانون — فارسی>

**قواعد:**
- <قاعدهٔ مشخص و قابل بررسی ۱>
- <قاعدهٔ مشخص و قابل بررسی ۲>

**چرا:** <دلیل یک‌خطی>

**چک:** <چطور AI یا انسان میفهمد رعایت شده — مثلاً دستور git، مسیر فایل، عدد تست>
```

**مراحل افزودن:**
1. شناسهٔ بعدی (`R-018` و بعد) را صادر کن.
2. قانون را با قالب بالا در بخش مربوطه (دسته) بنویس.
3. ردیف آن را به جدول «فهرست قوانین فعال» اضافه کن.
4. در `README.md` بسته، تعداد قوانین را به‌روز کن.
5. کامیت فارسی بزن و پوش کن (طبق R-002) — **این قانون جدید خودش باید رعایت شود.**

**قوانین 🔴 حذف‌نشدنی:** با هیچ بهانه‌ای غیرفعال یا حذف نمیشوند؛ تغییرشان فقط با تأیید صریح کاربر.
